## 2. 약관 조건(5절 마감 표 'XJ 원천 보조 행 약관 근거 \| R1a 제출 전 \| 원천 쪽 설계 시험하지 않음', 7.2-10)

- `--aux-lic-ref '<문구>'` 가 없으면 원천 쪽 단위를 만들지 않고 XJ-1·XJ-2 를 '시험하지 않음'으로 둔다(가설 표에 행을 남기고 Holm 에는 p 1). 이것이 기본값이다.
- 문구를 주면 (1) 작업 트리 계획 문서의 '## 개정 이력' 절 안에 있고, (2) 커밋된 판(`git show HEAD:<계획>`)의 개정 이력 절에도 있으며, (3) T0 판(`git show 2678100:<계획>`)에는 없어야 한다(새 개정 이력 항목이 R1a 제출 전에 커밋되어 있어야 한다, 5절 마감 표). 어긋나면 실행을 거부한다. 문구를 처음 더한 계획 커밋(`git log -S`)을 찾아 unit.json 의 aux_lic·aux_lic_commit 에 적는다.
- 계획 문서가 없는 환경(Rescale 묶음)에서는 대조를 건너뛰지 않는다. 로컬에서 `--count-only --aux-lic-ref '<문구>' --write-lic-token` 으로 만든 약관 표지(`data/processed/xbatch/XJ_tempderived_aux_labels/inputs/xj_aux_lic_token.json`: 문구, 문구 sha256, 계획 문서, T0 커밋, 문구를 더한 계획 커밋)가 있어야 하고, 문구·sha256·T0 커밋이 표지와 같아야 한다. 표지가 없거나 다르면 실행을 거부한다. 표지는 xbatch_core.PAYLOAD_OPTIONAL 로 묶음에 들어간다(있을 때만). 시험 (w).
- 자료원별 근거: `--aux-src-sources` 에 남긴 자료원만 쓴다(기본 두 자료원). 하나만 근거가 있으면 그 자료원만 쓴다. 둘 다 빠지면 '시험하지 않음'.
- 스모크(`--smoke`)는 코드 경로 점검이라 결과를 쓰지 않으므로 약관 조건을 적용하지 않고 원천 쪽 경로를 지난다(cfg 의 smoke_lic 에 적는다). 스모크 표는 봉인 폴더의 `xj_smoke_*` 이며 판정에 쓰지 않는다.

## 3. 원천 쪽 설계

| 항목 | 처리 |
|---|---|
| 기준(w = 0) | LG(h40.run_ctx)와 같은 학습 행렬과 같은 키다. h54.TUnit 의 rows_D·rows_R(h42.stack_rows, 유사라벨 색인 h42.ps_index = h40 'lg-ps')을 그대로 쓴다. 시험 (h)가 합성 문맥에서 h40.run_ctx 와 D0·D1·R1 키의 블록 SSE 가 정확히 같음을 확인한다 |
| 보조 행의 위치 | 기준 학습 행렬(원천 행, 선택 라벨 행, 유사라벨 행) 끝에 붙인다. 유사라벨 행 수 round(r × 원천 직접 라벨 행 수)는 바꾸지 않는다(w 에 따른 차이가 보조 행에서만 나게 한다) |
| 가중 | CatBoost sample_weight: 보조 행 w, 그 밖 1. w = 0 은 보조 행을 넣지 않고 sample_weight 도 주지 않는다(LG 와 같다) |
| 보조 행의 목표 | D0·D1 은 y. R1 은 y − E0·s(원천 행과 같은 E0 앵커) |
| E0 | 직접 라벨 원천으로만 구한다(LG 와 같다). 보조 행은 P0, κ 수축의 사전값, R1 앵커에 들어가지 않는다. 계획이 원천 쪽 방법을 D0, D1, R1 로 정했고 P0·P1 대비를 두지 않았으므로 보조 행은 ML 학습 행에만 더하는 것으로 읽었다 |
| LG 원천 규칙 | 보조 행에 h40.Data.source_idx 와 같은 순서와 코드를 쓴다: (1) 대상 지역(macro) 안의 보조 행 제외(대상 셀 제외에 해당), (2) 대상 셀에서 100 km 안(위도 1° 사전 걸러냄 뒤 haversine 최솟값 < buffer_km)의 보조 행 제외. 시험 (k)가 직접 라벨 행에 적용하면 source_idx 와 같은 집합임을 확인한다. 원천 쪽 대상은 주 4지역(macro)뿐이라 하위 지역 규칙(상위 macro 제외)은 구현하지 않았다(하위 지역 대상이면 ValueError) |
| 표지 열 판 | '지온 유도 표지 열을 입력에 더한 판 포함' 을 같은 단위의 추가 변형으로 둔다: w ∈ {0.1, 0.3, 1} 에서 학습·예측 행렬 끝에 표지 열(보조 행 1, 그 밖 0, 예측 행 0)을 더한다. 대비 기준은 표지 열이 없는 w = 0 키다. 가설 표 15행(Holm m = 15)은 표지 열이 없는 판만 센다. 표지 열 판은 `xj_tests.csv` 의 XJ-d(서술) 행이다 |
| 키 이름 | `<방법>@w<w>`(예: R1@w0.1, D1@w1), 표지 열 판 `<방법>@wf<w>`. R1 은 λ 0.25·0.5·1.0 을 같은 g 로 저장한다(판정은 0.25) |
| n·추출 | n {0, 10, 40}(|A| 미만), 추출 5(n = 0 은 1, h40.cells_of), seed 0·1, 분할 1–5 의 h40 구조 규칙(h54.split_plan) |

## 4. 대상 쪽 설계

| 채점 | B 블록의 직접 라벨 eval_mask 셀만(h40.build_ctx 의 채점 셀). 보조 행은 채점에 없다(시험 (j)) |
| 키 | P0, P1(LG 와 같은 키), P1@w0.1·0.3·1(learner none, seed −1) |

## 6. 불일치와 확인 필요 사항

1. **묶음 목록**: 4절 묶음 목록에 `data/processed/fidelity_base_v4.csv` 와 `fidelity_base_v4_labels.csv` 가 없다. 대상 쪽 보조 행(F3_ext_temp)은 v4 표에만 있고(티베트 실행 표에는 없다), 약관 열은 labels 표에 있다. 두 파일과 실행 표의 토양 표 연결(`run_tables/*/e5_soil_tdd_v3.csv`)을 xbatch_core.PAYLOAD_INPUTS 에 더했고(모듈 PAYLOAD_EXTRA, 시험 r), 약관 표지는 PAYLOAD_OPTIONAL 에 더했다. 허용 표지가 있는 본 실행(스모크 아님)에서 대상 쪽 입력(티베트 실행 표와 토양 표 연결, v4 보조 행 표·토양 표, v4 약관 표)이 없으면 건너뛰지 않고 중단한다(require_inputs). 로컬 세기·스모크에서는 건너뜀으로 기록한다.
2. **비용**: 계획은 '약 0.3 워커·시간[추정]' 이다. 이 구현은 등록 범위(주 4지역 × 분할 5 × n {0, 10, 40} × 추출 5 × seed 2 × 방법 3 × 변형 7(기준 1, w 3, 표지 열 판 3))를 모두 적합하고, D1 은 유사라벨 행(원천 행 수의 10배)을 포함한다. `--count-only` 의 추정 누적 시간은 작업 요약에 적었다. 계획대로 R1a 의 마지막 순서이고 시간 상한에 걸리면 뺀다.
3. **원천 쪽 약관 근거**: 현재 개정 이력에 근거가 없으므로 기본 실행에서 원천 쪽은 '시험하지 않음'이다. 근거를 적으면 그 문구를 `--aux-lic-ref` 로 준다.
4. **'지온 유도 표지 열을 입력에 더한 판 포함'**: 가설 표의 대상인지 문구가 정하지 않는다. Holm m = 15 가 표지 열이 없는 판의 수(6 + 3 + 6)와 같으므로 표지 열 판은 서술로 두었다.
5. **재현 관문과 numpy 판(미해결)**: 1절은 같은 노드 종류와 elm·hematite 사이의 관문 허용 오차를 |ΔSSE| 0 으로 정했다. 그러나 원천 쪽 기준인 LG 작업은 numpy 2.4.6 이었고(`results/rescale_lg/logs_lg/deps.log`), R1a 는 1절 '패키지 판'에 따라 numpy 2.1.1 을 고정한다(`scripts/rescale/xbatch_constraints.txt`). 1절 근거 기록(WF9 재현 점검 최대 0)은 numpy 판이 같은 두 노드 사이의 값이라 이번 관문에서 차 0 이 보장되지 않는다[미확인]. 대상 쪽 기준(LGD 티베트)은 로컬 산출이라 판 기록이 없다. 구현은 문자 그대로 허용 오차를 유지하고 두 쪽 판을 관문 표와 메타에 적는다. 관문이 numpy 판 때문에 실패하면 1절에 따라 판정을 멈추고 원인을 개정 이력에 적는다. 계획 결정(관문 수준 또는 R1a 의 numpy 판)이 필요하다.
