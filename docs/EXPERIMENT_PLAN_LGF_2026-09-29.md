## 1. 목적

### 1.1 F. 표형 파운데이션 모델 확장

- 심사 질문 '표형 파운데이션 모델을 시험했는가'에 모델 하나(TabPFN v2, LGT)가 아니라 계열로 답한다.
- 공개 가중치 표형 파운데이션 모델 가운데 연구·게재 제약 없이 이 환경에서 쓸 수 있는 모델을 LGT 와 같은 규약(같은 대상, 분할, 라벨 추출, 컨텍스트 규칙)으로 시험한다. 점검 결과 조건을 모두 만족한 모델은 TabICL v2 하나다(3.1).
- 짝 대조군은 두 개다. 같은 컨텍스트 행으로 적합한 CatBoost(`catboost_ctx`, LGF 조각 안에서 다시 적합)와 LGT 의 TabPFN v2(LGT 조각을 읽기 전용으로 짝지음, 3.4)다.

### 1.2 N. 신경망 초모수 강건성

- LG 학습기 축의 신경망 4종(MLP, TabM, FT-Transformer, RealMLP)은 기본 초모수로만 적합했다. 코드를 읽은 결과 MLP·TabM·FT-T 는 배치 8,192, epoch 100, patience 6 이다. 원천 약 15,000행에서는 epoch 당 2 step, 알래스카 계열 대상(원천 3,860행)에서는 1 step 이므로 전체 갱신이 최대 100–200회다. 문헌의 설정(배치 256–1,024, patience 16)과 차이가 크다. 따라서 '신경망이 조정되지 않았다'는 지적에는 실질이 있다.
- 원천 자료 안에서만(대상과 100 km 버퍼 제외, 원천 지역 하나 제외 교차검증) 초모수를 고른 조정판을 만들고 D0·R1 에서 기본판과 짝짓는다. LGX N3(L30, CatBoost 용량과 조정)의 신경망 판이다.
- 기본판은 LG 본 실행(Rescale, T4, torch 2.4.1, numpy 2.4.6)과 하드웨어와 판이 다르다. 그래서 기본판도 로컬에서 같은 조건으로 다시 적합해 조각 안에서 짝을 닫는다.

### 1.3 대응하는 심사 지적

| 지적 또는 공백 | LGF 항목 | 기존 등록 |
|---|---|---|
| 표형 파운데이션 모델을 시험했는가 | F1–F5(TabICL v2) | LGT L32–L37(TabPFN v2) |
| 모델 하나의 결과를 계열의 결론으로 쓸 수 있는가 | F3(두 모델 사이의 대비), 3.6 의 계열 문장 규칙 | 없음 |
| 컨텍스트 상한 10,000행이 결론을 정했는가 | F6(TabICL 에 원천 전체를 컨텍스트로 준다) | LGT L37 의 tgt 변형(원천 행 제거) |
| 신경망이 조정되지 않았다 | N1–N4 | LGX N3(L30, CatBoost), L5·L26(기본 초모수) |

## 2. 공통 규약

### 2.1 LG·LGX·LGT 와 같게 두는 것

자료(`load_base`, F4_direct 17,467셀), 대상과 원천 정의(LG §1, 100 km 버퍼), 하위 지역 대응표(`data/processed/lg_subregion_map_v1.csv`), 분할(`half_split_blocks` split_seed 1–5, 중복·무효 분할 규칙), 라벨 추출(`h40.draw_cells`, 같은 seed 식), 채점 셀(B 블록의 `eval_mask` 셀), 물리식 계수(E0 = 원천 전체의 최소제곱, E_n = (n·E_ls + κ·E0)/(n + κ), κ = 10), 학습기 seed 0·1, 입력 x25, 기준 λ(D0 1.0, R0·R1 0.25)와 λ ∈ {0.25, 0.5, 1.0} 의 사후 적용, 키 구조(method, learner, alpha, placement, n, draw, seed, lam), Δ 의 정의(Δ(A − B) = RMSE(A) − RMSE(B), cm, 음수면 A 가 낫다), 주 CI(`h4_common.boot_delta_blocks`, 재표집 10,000회, 셀 가중과 블록 등가중), 4분 판정(우세, 열세, 동등, 미결정), 동등성 한계(주 0.5 cm, 보조 1.0 cm), 층화 평균의 풀과 풀 지역 수 표기, 보조 CI(지역 블록 공통 재표집), Holm 보정 p(보조 열), 효과 크기 표기, 6A.5a 의 공통 규칙(분할 완결성, 판정할 수 없는 대비, 동등성 p, 확인적 표지, 맹검 표지), LG 계획서 6C 개정 12 의 운영 규칙(조각 상태 ok·partial·failed 와 재실행, 종료 코드, 단위마다의 GPU 재확인, 잠금 파일, 스모크 산출 제한). 개정 12 는 이 문서 작성 시점의 LG 계획서 작업 사본(커밋 전) 기준이다. 번호가 바뀌면 내용으로 대응시킨다.

| 항목 | 규칙 |

| 짝 키 | 학습기 짝 대비(서로 다른 학습기, 또는 기본판과 조정판)는 두 쪽에 모두 있는 (method, alpha, placement, n, draw, seed, lam) 키만 쓴다. 뺀 키 수를 대비 행의 `n_unpaired` 열에 적는다(LG 6C 개정 12 와 같다). 같은 학습기 안의 대비와 곡선은 저장된 키 전부를 쓴다 |

| 실패 처리 | 비유한 예측이 있는 키는 저장하지 않고 실패 표(`lgf_failed.csv`, `lgfn_failed.csv`)에 남긴다. 짝의 한쪽이 없는 키는 위 짝 키 규칙으로 대비에서 빠진다 |

### 2.3 F 가 LGT(6C.2–6C.4)를 그대로 따르는 것

- 방법 P0, P1, D0, R0, R1 의 정의(6C.3 의 표). n = 0 에서 R1 은 R0 과 같은 적합을 쓴다. 세 방법은 같은 (n, 추출, seed)에서 같은 컨텍스트 행을 쓰고 목표만 다르다.
- 컨텍스트 규칙(6C.4) 전부: 상한 C = 10,000행, 대상 라벨 행 1배(부분 추출 없음), 원천 예산 m = min(원천 행 수, C − max(T, 1,000)), 지역 비례 층화 중첩 부분 추출, 부분 추출이 없는 대상(원천 3,860–3,861행), 큰 n 의 규칙, T > 9,000 의 규칙, 행 순서(원천 행 다음 대상 행), 채점 셀 한 번 예측과 CUDA 메모리 부족 때의 4,096행 묶음 재예측.
- 부분 추출 seed 는 LGT 의 문자열을 그대로 쓴다: seed_of('lgt-ctx', 대상, 모드, 분할, 학습기 seed). 이름을 바꾸면 TabPFN 과 같은 행이 되지 않는다.
- 구현은 h43 의 컨텍스트 함수(`ctx_order`, `src_budget`, `context_rows`, `build_X`, `build_y`, `coef_n`, `ctx_sha`)를 importlib 로 불러 그대로 쓴다. 새로 구현하지 않는다.
- `catboost_ctx` 의 정의(반복 200, 학습률 0.05, 깊이 3, l2 3, random_seed = 학습기 seed, 입력 x25 원값, 학습과 채점 Pool 의 thread_count 지정. h43 의 `cb_fit_predict`).
- 주 설정의 범위: n 전 격자 {0, 3, 10, 40, 160, 320, 1,000, 전량}(\|A\| 미만과 전량), 추출 5, seed 2, 대상 27 과 그 실행 순서.

### 2.4 F 가 LGT 와 다르게 두는 것

| 항목 | LGT | LGF-F |
|---|---|---|
| 새 학습기 | `tabpfn`(TabPFN v2) | `tabicl`(TabICL v2) |
| 입력의 결측 | NaN 을 그대로 넘기고 TabPFN 이 처리한다 | pandas DataFrame 으로 넘긴다. TabICL 2.0.2 의 전처리(`TransformToNumerical`)가 수치 열의 결측을 SimpleImputer(평균, 컨텍스트 행으로 적합)로 채운다. 2.0.2 는 numpy 배열의 NaN 을 받지 않는다 |
| 열 종류 | 컨텍스트가 100행을 넘으면 `cci_valid` 를 범주형으로 추론한다(6C 개정 12) | `TransformToNumerical` 은 수치 자료형 열을 연속형으로 다룬다(설치된 소스 확인). 그 뒤의 열 처리(상수 열 제거, 이상치 처리, 멱변환 앙상블)는 2.0.2 의 기본값이다 |
| TabPFN 값 | 조각 안에서 적합 | LGT 조각을 읽기 전용으로 짝짓는다(3.4) |
| `catboost_ctx` | LGT 조각 안에서 적합 | LGF 조각 안에서 다시 적합한다(같은 정의, 같은 컨텍스트 행) |
| 민감도 | d3, d10, rid, tgt | full(원천 전체를 컨텍스트로, 3.3) 하나 |
| GPU | 9·7·6·5 | 4(6절) |
| 실행 파이썬 | 전역 python3 | `.venv_lgf/bin/python`(같은 torch·numpy·pandas·scikit-learn·catboost 판에 tabicl 추가) |

입력 처리의 두 차이(결측 대치, 열 종류)는 학습기 정의의 일부로 둔다. 두 모델의 기본 사용법을 바꾸지 않기 위해서다. F3 의 해석에 이 차이를 적는다.

### 2.5 N 의 학습 규약

- 학습 행은 LG 학습기 축과 같다. 원천 전체 ∪ 대상 라벨 n개이고 가중이 없다. 컨텍스트 상한은 없다.
- 입력 전처리, 목표 척도, 조기 종료 검증은 기본판이 LG 의 코드 경로 그대로다(4.1). 조정판의 전처리는 4.2 의 공간 안에서 고르며 통계는 학습 행으로만 구한다.
- 대상, n 격자, 추출, seed, 분할, 방법은 4.4 에 적는다.

### 3.2 학습기 정의

| 학습기 | 설정 |
|---|---|
| `tabicl` | `TabICLRegressor(n_estimators=8, norm_methods=None(= none, power), feat_shuffle_method='latin', outlier_threshold=4.0, batch_size=8, model_path=<3.1 의 절대 경로>, allow_auto_download=False, checkpoint_version='tabicl-regressor-v2-20260212.ckpt', device='cuda', use_amp='auto', use_fa3='auto', offload_mode='auto', random_state=<학습기 seed>, n_jobs=None, verbose=False, inference_config=None)`. fit 의 `kv_cache=False`. 모두 2.0.2 의 기본값이고 바꾼 것은 가중치 경로, 자동 내려받기 금지, 장치, random_state 뿐이다. 입력은 x25 원값을 열 이름이 있는 DataFrame(float32, 결측은 NaN)으로 넘긴다. 예측은 `predict(X, output_type='mean')` 이다. 초모수 조정과 미세 조정은 하지 않는다 |
| `catboost_ctx` | LGT 와 같다(2.3). 같은 프로세스에서 TabICL 과 같은 컨텍스트 행렬과 목표로 적합한다 |
| `tabpfn` | LGF 는 적합하지 않는다. LGT 조각의 키를 3.4 의 조건으로 읽어 짝짓는다 |

구현 규약:
- `use_amp='auto'` 는 컨텍스트가 1,024행 이상이거나 특징이 60개 이상이면 혼합 정밀도를 켠다. F 의 컨텍스트는 모두 3,860행 이상이므로 모든 적합에서 켜진다. FA3 는 제작자 설명상 Hopper GPU 용이고 설치된 경우에만 쓰인다. 이 환경의 설치 여부는 확인하지 않았다. 실제 적용 값(AMP, FA3, offload 방식)을 조각에 기록한다.
- 스레드: `n_jobs=None` 을 유지한다. 2.0.2 의 `predict` 는 `n_jobs > 0` 이면 torch 스레드를 max(논리 코어 수, n_jobs)로 올린다(설치된 소스에서 확인). 준비 단계 기록에는 2.2.0 에서 고쳐졌다고 되어 있으나 이 문서에서는 확인하지 않았다. 스레드는 `torch.set_num_threads(2)` 와 OMP·MKL·OpenBLAS·NUMEXPR 환경 변수로 제한한다.
- 가중치 적재: 2.0.2 의 `fit` 은 적합마다 체크포인트를 `torch.load` 로 다시 읽는다. 하네스는 워커마다 체크포인트 사전(config, state_dict)을 한 번 읽어 두고 적합마다 그 사전으로 모델을 만든다(`_load_model` 만 바꾼 하위 클래스). 가중치와 계산은 같다. 스모크에서 원래 클래스와의 예측 차(최댓값)가 1e-6 cm 이하인지 확인하고, 넘으면 원래 클래스를 쓴다.
- 체크포인트의 SHA-1 이 3.1 의 값과 다르면 실행하지 않는다. `HF_HUB_OFFLINE=1` 을 둔다.
- `SimpleImputer` 는 컨텍스트에서 모두 결측인 열을 버린다(scikit-learn 1.3.0 의 기본). 등록 범위에서 이런 열이 생기는지 `--count-only --dry-build` 로 확인하고 수를 적는다.

### 3.3 방법

| id | 컨텍스트 행의 목표 | 예측 | 기준 λ |
|---|---|---|---|
| P0, P1 | 해석식 | E0·s, E_n·s. 모든 조각에 저장한다 | 없음 |
| D0 | 원천 행 y, 대상 라벨 행 y | f(x) | 1.0 |
| R0 | 원천 행 y − E0·s, 대상 라벨 행 y − E0·s | E0·s + λ·g(x) | 0.25 |
| R1 | 원천 행 y − E0·s, 대상 라벨 행 y − E_n·s | E_n·s + λ·g(x) | 0.25 |
| D0@full, R1@full | D0, R1 과 같다 | D0, R1 과 같다 | 1.0, 0.25 |

**full 변형**: 컨텍스트 상한을 두지 않는다. 원천 행 전부(`ctx_order` 의 순서)와 대상 라벨 행(1배)을 넣는다. 학습기는 `tabicl` 과 `catboost_ctx` 다. full 의 `catboost_ctx` 는 원천 전체 ∪ 대상 라벨로 학습하므로 LG 의 `catboost_lo` 와 같은 정의다(로컬에서 적합). 목적은 TabPFN 의 사전 학습 범위에서 정한 상한 10,000행이 TabICL 의 결과를 제한했는지 보는 것이다. R1@full 의 n = 0 은 R 목표의 적합(E_n = E0)이다.

### 3.4 TabPFN v2 와의 짝(LGT 조각 읽기 전용)

LGF 조각과 LGT 조각의 짝은 같은 컨텍스트 행일 때만 성립한다. 작업 단위(대상, 모드, 분할)마다 다음 조건을 모두 확인한다.

| 조건 | 내용 |
|---|---|
| 1. 조각 상태 | LGT 조각(`data/processed/lgt/shards/lgt__gpu__<대상>__<모드>__s<분할>_*`)의 `unit.json` 이 있고 status 가 ok 또는 partial 이다 |
| 2. 설정 | LGT 조각의 설정에서 컨텍스트 매개변수(ctx_max 10,000, ctx_reserve 1,000, ctx_src_min 1,000, 중복 배수 1, κ 10, seed 2, 추출 5, n 격자)와 하위 지역 대응표 이름이 LGF 와 같다 |
| 3. 물리식 | P0, P1 키의 셀 가중 RMSE 가 1e-9 cm 안에서 같다 |
| 4. 컨텍스트 해시 | 같은 (방법, n, 추출, seed)에서 LGT 의 `tabpfn` 행과 LGF 의 `tabicl` 행의 `ctx_sha`(컨텍스트 행렬 float32 와 목표 float64 의 SHA-1 앞 12자, h43 의 `ctx_sha`)가 같다. 한 키라도 다르면 그 단위의 TabPFN 키 전부를 짝에서 뺀다. LGT 에 없는 키는 짝 키 규칙(2.2)으로 빠진다 |
| 5. 채점 블록 | 두 조각의 채점 블록 집합과 블록별 셀 수가 같다(`BlockStore.merge` 의 확인) |

- 조건을 모두 통과한 단위의 `tabpfn` 키(LGT 주 설정 `ctx_set = main` 의 키만)를 LGF 집계의 BlockStore 에 병합한다. 단위별 통과 여부와 사유는 `lgf_gate.csv` 에 남긴다.
- 보조 점검: LGF 의 `catboost_ctx` 와 LGT 의 `catboost_ctx` 를 키별 셀 가중 RMSE 로 대조한다(허용 차 0.02 cm). 어긋나도 짝에서 빼지 않고 표시만 한다. 두 실행의 스레드 수가 다르면 그 값을 함께 적는다(CatBoost 의 스레드 수에 따른 재현성은 확인하지 못했다).
- h43 의 코드 해시: LGF 조각에 기록한 h43 SHA-1 과 LGT 조각의 `code_sha` 가 다르면 경고한다. 짝의 판단은 조건 4 로 한다.
- 두 적합은 같은 서버, 같은 GPU 기종(RTX 3090), 같은 torch·numpy·pandas·scikit-learn·catboost 판에서 돈다. 프로세스와 GPU 번호만 다르므로 같은 플랫폼으로 본다.
- LGT 결과가 없거나 조건을 통과한 단위가 없으면 TabPFN 을 쓰는 대비(F3, F4 의 병기 열)는 '행 없음'이다. 다른 가설의 판정에는 영향이 없다.

### 3.6 가설과 판정(결과 열람 전 고정)

I = `tabicl`, C = `catboost_ctx`, T = `tabpfn`(LGT 조각). 모든 대비는 기준 λ 와 4분 판정을 쓰고, 따로 적지 않으면 주 4지역 층화 평균이다.

| id | 가설 | 판정 |
|---|---|---|
| LGF-F1 (라벨 0 직접 예측, 확인적) | 라벨 0 에서 TabICL 직접 예측(D0)은 원천 계수 물리식(P0)을 넘지 못한다 | n = 0 의 D0[I] − P0(λ 1.0)가 우세가 아니면 지지. 문장 '표형 파운데이션 모델 TabICL v2 를 학습기로 써도 직접 ML 은 라벨 0 전이에서 원천 계수 물리식을 넘지 못한다'. 우세이면 기각하고 L1 의 결론을 'TabICL 을 제외한 학습기 한정'으로 적으며 TabICL 의 D0 곡선을 마스터 곡선에 더한다. 지역 행, 3지역 보조 열, D0[C] − P0 를 병기한다 |
| LGF-F2 (학습기 동등성) | R1 에서 TabICL 과 같은 컨텍스트 CatBoost 의 차이는 동등성 한계 안이다 | L32 와 같은 형식이다. R1[I] − R1[C] 를 n ∈ {0, 10, 40, 160, 전량} 에서 본다. 다섯 n 모두 동등(λ 0.25 와 1.0)이면 '동등(한계 0.5 cm)'. 우세와 열세가 없고 미결정이 있으면 '차이를 확인하지 못함'. 우세 또는 열세인 n 이 있으면(기준 λ 0.25 로 판정) n, 방향, 크기를 표로 보고하고 λ 1.0 의 대비를 병기한다. 2.2 의 λ 조합 규칙을 쓴다. n ∈ {3, 320, 1,000} 과 D0, R0 의 같은 대비는 보조다 |
| LGF-F3 (파운데이션 모델 사이, 방향 중립) | 방향을 정하지 않는다 | 3.4 의 짝 조건을 통과한 단위만 쓴다. R1[I] − R1[T] 를 n ∈ {0, 10, 40, 160, 전량} 에서, D0[I] − D0[T] 를 n = 0 에서 본다(여섯 대비). 여섯 대비 모두 동등이면 'TabICL v2 와 TabPFN v2 의 차이는 한계 0.5 cm 안이다'. 우세 또는 열세인 대비가 있으면 대비, n, 방향, 크기를 보고한다. 그 밖은 '두 모델의 차이를 확인하지 못함'. 두 모델의 차이에는 입력 처리의 차이(2.4 의 결측 대치와 열 종류)가 포함된다는 점을 판정 행에 적는다 |
| LGF-F4 (순가치와 전량) | TabICL 잔차(R1)는 같은 라벨로 재보정한 물리식(P1)을 넘는다 | L33 과 같은 형식이다. R1[I] − P1 을 n ∈ {3, 10, 40, 160, 320, 전량} 에서 보고 우세인 최소 n 을 4지역 평균인 n 과 2–3지역 평균인 n 으로 나눠 보고한다. n ≤ 40 에서 우세이면 '희소 라벨에서도 TabICL 잔차의 순가치가 있다'. 어느 n 에서도 우세가 아니면 'TabICL 잔차의 재보정 물리식 대비 순가치는 확인되지 않았다'. 열세인 n 은 표로 보고한다. R1[C] − P1 과 R1[T] − P1(짝 조건 통과 단위)을 병기한다. 추가 행: 전량의 R1[I] − P0(L35 형식). 우세이면 '라벨 전량에서 TabICL 잔차는 원천 계수 물리식을 넘는다' |
| LGF-F5 (라벨 0 잔차, 방향 중립) | 방향을 정하지 않는다 | n = 0 의 R0[I] − P0 의 4분 판정을 보고한다(L34(b) 형식). 우세 '라벨 0 에서 TabICL 잔차는 원천 계수 물리식보다 오차가 작다', 열세 '오차가 크다', 동등 '구별되지 않는다(한계 0.5 cm)', 미결정 '차이를 확인하지 못함'. R0[C] − P0 를 병기한다 |
| LGF-F6 (컨텍스트 상한, 방향 중립) | 방향을 정하지 않는다 | R1@full[I] − R1[I], D0@full[I] − D0[I] 를 n ∈ {0, 10, 전량} 에서 본다(공통 추출 0, 1 로 짝짓는다). 모두 동등이면 '컨텍스트 상한 10,000행의 영향은 한계 0.5 cm 안이다(TabICL)'. R1@full[I] − R1[I] 가 우세인 n 이 있으면 '원천 전체를 컨텍스트로 주면 TabICL 잔차의 오차가 줄어든다(n)', 열세이면 '늘어난다(n)'. 그 밖은 n 별로 서술한다. R1@full[I] − R1@full[C] 를 병기한다(원천 전체 조건의 학습기 대비) |

**판정 세부 규칙(F)**

| 항목 | 규칙 |
|---|---|
| 풀 | 2.2 와 같다 |
| 대상별 행 | 실행한 대상의 곡선(두 기준선 Δ, 라벨 순가치, 4분 판정)을 `lgf_curve.csv` 에 싣는다. 러시아 C 와 그린란드는 점 추정만이다 |
| 분할 완결성 | 6A.5a 와 같다. F1 은 확인적이므로 분할 미완결 대비를 쓰면 '판정 불가(분할 k/K)'. 나머지는 '부분(분할 k/K): '을 붙인다 |
| 판정할 수 없는 대비 | F1 은 대비가 없거나 4분 판정이 나오지 않으면 '판정 불가'다. F2 는 LG 6C.6 의 L32 규칙(판정이 나온 대비에 우세 또는 열세가 있으면 그 n 을 보고하고 '부분(대비 k/m)')을 따른다. F3 는 판정이 나온 대비만으로 서술하고 '부분(대비 k/6)'을 붙이며, 판정이 나온 대비가 없으면 판정 불가다. F4 는 L33 규칙을 따른다. F5, F6 은 대비가 없으면 판정 불가다 |
| 계열 문장 | '표형 파운데이션 모델 2종(TabPFN v2, TabICL v2)'을 주어로 한 문장은 두 모델의 같은 형식 판정이 같을 때만 쓴다. 라벨 0 직접 예측은 F1 과 LGT L34(a)가 모두 지지일 때, 학습기 동등성은 F2 와 L32 가 모두 '동등'일 때다. 다르면 모델별로 쓴다. 시험하지 않은 모델로 일반화하지 않는다 |
| L1 과의 관계 | F1 이 기각이면 L1 의 결론 문장에 한정어를 붙인다(위 표). F1 이 지지이면 L1, L30, LGT L34(a)와 함께 '학습기 종류와 무관'의 근거 목록에 TabICL 을 더한다 |
| Holm 묶음(보조) | F1 의 1개, F2 의 기준 λ 5개, F4 의 6개와 전량 1개, F5 의 1개를 한 묶음으로 양측 부트스트랩 p 를 보정한다. F2 의 동등성 p 는 따로 보정한다. 판정에 쓰지 않는다 |
| 맹검 표지 | 5절의 표를 따른다 |

## 4. N: 신경망 초모수 강건성

### 4.1 학습기와 기본판

기본판은 LG 의 코드 경로를 그대로 부른다(h40 의 `run_ctx` 와 `Fitter`). 아래 값은 코드를 읽어 확인한 것이다.

| 학습기 | 코드 경로 | 기본 설정 |
|---|---|---|
| `mlp` | `h40.mlp_fit`(`tab_models._torch_mods` 의 MLP, `tab_models._epochs_fit`) | 25→256→128→64→1, 앞 두 층 ReLU·BatchNorm·Dropout 0.1. Adam lr 1e-3, weight_decay 1e-5, SmoothL1(학습 행의 평균·SD 로 z 변환한 y), 배치 8,192, epoch 100, 학습 행 무작위 10 % 검증의 MSE 로 조기 종료(patience 6, 최소 개선 1e-4, 최적 상태 복원), 기울기 절단 5. 입력은 학습 행렬의 중앙값 대체와 표준화(`h40._prep_stats`) |
| `tabm` | `m1_core.fit_model` → `tab_models._fit_torch('tabm')` | 공유 몸통 25→256(ReLU·BatchNorm·Dropout 0.1)→128(ReLU·BatchNorm)과 독립 헤드 k = 8개(128→64→1), 헤드 출력 평균. Gorishniy 2025 의 TabM(BatchEnsemble 어댑터)이 아니라 다중 헤드 MLP 다. 학습 규약은 `mlp` 와 같다 |
| `ftt` | `m1_core.fit_model` → `tab_models._fit_torch('ftt')` | 수치 특성마다 선형 토큰화와 CLS 토큰, d = 64, head 8, 블록 3, FFN 128, GELU, pre-norm, dropout 0.1 하나(attention·FFN·잔차 공통), 출력 LayerNorm + Linear. Adam lr 5e-4, 그 밖의 학습 규약은 `mlp` 와 같다. 원 논문 기본값(d 192, ReGLU, FFN 비 4/3, dropout 3종 분리, AdamW lr 1e-4)보다 작다 |
| `realmlp` | `h40.realmlp_fit_predict`(pytabkit 1.7.3 `RealMLP_TD_Regressor`) | TD 기본값(은닉 [256]×3, pbld 수치 임베딩, front scale, dropout 0.15 flat_cos, wd 0.02 flat_cos, lr 0.2 coslog4, Adam β2 0.95, 배치 256, epoch 256, 무작위 20 % 검증으로 최적 epoch 선택). 입력은 h40 이 표준화한 x25. 이미 문헌 기본값으로 돌았다 |

원고에서는 `tabm` 과 `ftt` 의 구조를 적거나 이름을 바꿔야 한다(9.2).

### 4.2 조정 공간

시도 0 은 모든 학습기에서 현행 기본값이고 4.1 의 코드 경로를 그대로 부른다. 무작위 시도에는 새 하네스 안의 매개변수화 클래스를 쓴다(h40, `tab_models` 는 고치지 않는다). MLP·TabM·FT-T 의 무작위 시도에 공통인 규약은 다음과 같다.

- 최적화기 AdamW, 조기 종료 patience 16(최소 개선 1e-4, 최적 상태 복원), 최대 epoch 300(FT-T 200).
- 검증 분리는 기본판과 같게 학습 행 무작위 10 %(`RandomState(seed).rand(n) < 0.1`), 기울기 절단 5, y 는 학습 행의 평균·SD 로 z 변환한다.
- 입력 변환 {표준화(`h40._prep_stats`), 분위 정규 변환(학습 행 중앙값 대체 뒤 scikit-learn `QuantileTransformer(output_distribution='normal', n_quantiles = min(1,000, 학습 행 수))`, 학습 행으로만 적합)}.
- 손실 {SmoothL1, MSE}.
- 마지막 배치가 1행이면 BatchNorm 이 있는 구성에서 그 1행을 뺀다(`h40.mlp_fit` 과 같은 처리).

| 학습기 | 설정 수 | 무작위 시도의 공간 | 근거(확인 수준) |
|---|---|---|---|
| `mlp` | 33(시도 0, 무작위 32) | 은닉층 수 UniformInt[1, 6], 폭 64–1,024(16 단위, 로그 균등), 모양 {일정, 층마다 절반(최소 16)}, 정규화 {BatchNorm, 없음}, dropout {0(확률 0.3), U[0, 0.5]}, lr LogU[1e-4, 1e-2], weight_decay {0, LogU[1e-6, 1e-3]}, 배치 {256, 512, 1,024, 2,048} | Gorishniy 2021 표 15(arXiv PDF 직접 읽음), Grinsztajn 2022(arXiv HTML 요약). lr 하한 1e-4 는 최대 300 epoch 안에서 수렴하지 않는 구간을 빼기 위해 올렸다 |
| `tabm` | 33(시도 0, 무작위 32) | 몸통 블록 수 UniformInt[1, 4], 몸통 폭 UniformInt[64, 1,024](16 단위, 블록 폭 일정), 헤드 수 k {8, 16, 32}, 헤드 은닉 64 고정, dropout {0, U[0, 0.5]}, lr LogU[1e-4, 5e-3], weight_decay {0, LogU[1e-4, 1e-1]}, 배치 {256, 512, 1,024, 2,048} | TabM 공식 저장소 README 요약(n_blocks, d_block, lr, wd 공간), pytabkit 1.7.3 소스의 TabM 'default' 공간(dropout, 직접 읽음). dropout 범위는 논문 부록 표에서 직접 확인하지 못했다 |
| `ftt` | 18(시도 0, 시도 1, 무작위 16) | 시도 1 = 원 논문 기본값의 근사(블록 3, d 192, head 8, FFN 256, dropout 0.1, lr 1e-4, wd 1e-5, 배치 512. 현행 클래스 구조라 ReGLU 와 dropout 3종 분리는 없다). 무작위: 블록 UniformInt[1, 4], d_token {64, 96, 128, 160, 192, 256}(head 8), FFN 비 U[2/3, 8/3], dropout U[0, 0.3], lr LogU[3e-5, 1e-3], wd LogU[1e-6, 1e-3], 배치 {256, 512, 1,024} | Gorishniy 2021 표 12·13(직접 읽음), Grinsztajn 2022. d 상한 256 과 lr 하한 3e-5 는 시간 예산 때문에 줄였다. 같은 논문 표 11 에 무작위 설정 몇 개로 좋은 값에 이른다는 관찰이 있다 |
| `realmlp` | 17(시도 0, 무작위 16) | pytabkit 1.7.3 의 `RealMLPParamSampler(is_classification=False, hpo_space_name='default').sample_params(seed)` 를 그대로 호출한다. num_emb_type {none, pbld, pl, plr}, add_front_scale {True 0.6, False 0.4}, lr LogU[2e-2, 3e-1], p_drop {0 (0.3), 0.15 (0.5), 0.3 (0.2)}, wd {0, 2e-2}, plr_sigma LogU[0.05, 0.5], act {relu, selu, mish}, hidden_sizes {[256]×3 (0.6), [64]×5 (0.2), [512] (0.2)}. epoch 256, 배치 256, 검증 20 % 는 고정 | pytabkit 소스(`models/alg_interfaces/nn_interfaces.py` 의 `RealMLPParamSampler`) 직접 읽음. Holzmüller 2024 의 HPO 기준선은 무작위 50회였으나 비용 때문에 16회로 둔다 |

- 설정 목록은 학습기·종류(D, R)마다 `seed_of('lgfn', 학습기, 종류, 시도 번호)` 로 한 번 뽑아 모든 대상에 같은 목록을 쓴다. RealMLP 는 이 seed 를 sampler 에 넘긴다. 목록은 첫 적합 전에 `lgfn_configs.json` 에 쓰고 해시를 조각 설정에 넣는다.
- RealMLP 의 표본 값은 `RealMLP_TD_Regressor` 의 생성자 인자로 넘긴다. 모든 키가 생성자 인자인지 `inspect.signature` 로 사전 점검에서 확인한다. numpy 자료형은 파이썬 자료형으로 바꿔 기록한다.

### 4.3 선택 규약

| 항목 | 규칙 |
|---|---|
| 선택 단위 | (대상, 모드) × 학습기 × 종류(D, R)마다 한 번 고른다. 분할, n, 추출마다 고르지 않는다. 원천 집합은 `h40.Data.source_idx(대상, 모드)` 로 정해지고 분할에 의존하지 않기 때문이다. 여러 대상을 묶어 한 설정을 고르는 전역 선택은 쓰지 않는다(대상 T 의 지역이 다른 대상의 원천 fold 로 들어가 T 의 라벨이 선택에 쓰인다) |
| 누설 규약 | 원천 행만 쓴다. 대상 셀과 100 km 버퍼는 `source_idx` 가 이미 뺐다. 대상 라벨, 대상 공변량, 채점 셀은 쓰지 않는다 |
| fold | 원천 macro 지역 가운데 30셀 이상인 지역을 하나씩 뺀다(`h42.MIN_REGION_CELLS` 와 같다). 30셀 미만 지역(Russia_C, Greenland, Tibet, Scandinavia, Svalbard)은 모든 fold 에서 학습 쪽이다. 조사 단계 계산으로 주 4지역 대상과 Alaska x 는 fold 4개다. 구현의 `--count-only` 가 대상별 fold 와 지역별 셀 수를 출력하고 개정 이력에 적는다 |
| fold 안 적합 | 전처리 통계와 y 척도는 fold 학습 행으로 구한다. 조기 종료 검증은 fold 학습 행의 무작위 10 %(RealMLP 는 pytabkit 의 20 %)다. 종류 D 는 y 를, 종류 R 은 fold 학습 행으로 다시 구한 E_tr 의 잔차 y − E_tr·s 를 학습한다(LGX N3 와 같다). 시도 0 은 4.1 의 코드 경로를 fold 자료에 그대로 적용한다 |
| 주 점수 | λ = 1.0 예측(D 는 ŷ, R 은 E_tr·s + g)의 fold 별 RMSE 를 지역 등가중으로 평균한다(N3 와 같다) |
| 보조 점수 | R 의 λ = 0.25 점수, 셀 가중 RMSE, 500셀 이상 fold 만의 점수, 시도 0 대비 점수 차. 선택에 쓰지 않는다. 30셀 fold 두 개가 주 점수의 절반을 차지하므로 보조 기준에서 선택이 바뀌는 (학습기, 종류, 대상) 수를 안정성 지표로 보고한다(Cawley·Talbot 2010, 서지와 초록 요지만 확인) |
| 탐색 | 무작위 탐색이다(Bergstra·Bengio 2012, 서지와 초록 요지만 확인). 1단계는 모든 설정을 seed 0 으로 적합한다. 2단계는 1단계 점수 상위(시도 0 제외) 3개(MLP, TabM) 또는 2개(FT-T, RealMLP)와 시도 0 을 seed 1·2 로 다시 적합하고, seed 3개 평균 점수가 가장 작은 설정을 고른다. 2단계는 신경망의 seed 분산 때문에 두며 N3(seed 0 단일 적합)와 다르다 |
| 동률과 실패 | 동률이면 매개변수 수(적합한 torch 모듈의 매개변수 수)가 적은 설정을 고른다. 적합 실패나 비유한 예측은 점수를 무한대로 둔다. 모두 실패하면 시도 0 을 고르고 표지를 남긴다 |
| 적용 | 고른 설정은 그 대상의 모든 분할, n(0 포함), 추출, seed, λ 에 같게 쓴다. D 설정은 D0 에, R 설정은 R1 에 쓴다. 대상 라벨로 다시 고르지 않는다 |
| 시도 0 이 선택된 경우 | 조정판 키를 기본판 키의 값으로 채운다(다시 적합하지 않음, Δ = 0). 행에 `sel_default` 표지를 남긴다 |
| 기록 순서 | 선택 표 `lgfn_nn_select.csv` 를 그 학습기·대상의 본 적합 전에 쓴다. 열은 대상, 모드, 원천 해시, 학습기, 종류, 시도, 설정 JSON, fold 별 RMSE, 주·보조 점수, 단계, seed, 선택 여부, 매개변수 수, 시간이다. 선택 표의 해시를 조각 설정에 넣는다 |

### 4.4 방법과 범위

| 항목 | 내용 |
|---|---|
| 방법 | D0(기준 λ 1.0), R1(기준 λ 0.25, λ ∈ {0.25, 0.5, 1.0} 사후 적용). n = 0 의 R1 은 E_n = E0 인 R 적합(= R0)이다 |
| 판 | 기본판 `<학습기>`(4.1 의 코드 경로, 로컬 재적합)와 조정판 `<학습기>_tuned`(4.3 의 선택 설정) |
| 동반 적합 | P0, P1(해석식), `catboost_lo` 의 D0·R1(CPU, 로컬 재적합, `h40.cb_fit` 과 같은 초모수, 학습과 채점 Pool 의 thread_count 2). LGF-N3 의 기준이다 |
| 대상 | 1순위: 주 4지역 x. 2순위: Alaska x(3지역 보조 열용) |
| 분할 | 1–5(주 4지역은 5개 모두 유효) |
| n 격자 | {0, 10, 40, 160, 전량} 가운데 \|A\| 미만과 전량. 러시아 W·E 는 {0, 10, 전량} |
| 추출 × seed | 2 × 2(LG 학습기 축과 같다) |
| 통과 | 통과 0 = n = 0(1순위 전 학습기, 분할 1–5)을 먼저 돈다. 통과 1 = n > 0. 확인적 가설 N1 의 구성 단위를 먼저 채우기 위해서다 |

적합 수(1순위, 학습기 하나, 판 하나): 레나 160, 캐나다 160, 러시아 W 80, 러시아 E 80, 합계 480건. 선택 단계의 fold 적합(1순위, 대상 4 × fold 4 = 16): MLP·TabM 은 1단계 33 × 2 × 16 = 1,056 과 2단계 최대 4 × 2 × 2 × 16 = 256, FT-T 는 576 과 192, RealMLP 는 544 와 192 다. 2순위(Alaska x)는 판마다 160건과 fold 4개다. `catboost_lo` 는 480건(2순위 160건)이다.

### 4.5 가설과 판정(결과 열람 전 고정)

l ∈ {`mlp`, `tabm`, `ftt`, `realmlp`}, l* = `l_tuned`, CB = `catboost_lo`(로컬). 모든 대비는 기준 λ 와 4분 판정을 쓰고, 따로 적지 않으면 주 4지역 층화 평균이다.

| id | 가설 | 판정 |
|---|---|---|
| LGF-N1 (조정한 신경망의 라벨 0 직접 예측, 확인적) | 원천 교차검증으로 초모수를 고른 신경망 직접 ML 도 라벨 0 전이에서 원천 계수 물리식을 넘지 못한다 | n = 0 의 D0[l*] − P0(λ 1.0)가 네 학습기 모두 우세가 아니면 지지. 문장 '원천 지역 하나 제외 교차검증으로 초모수를 골라도 신경망 직접 ML 은 라벨 0 전이에서 원천 계수 물리식을 넘지 못한다'. 하나라도 우세이면 기각하고 L1 의 결론을 '기본 초모수 한정'으로 적으며 해당 학습기의 조정판 곡선을 마스터 곡선에 더한다. 보조 행: 로컬 기본판의 D0[l] − P0(n = 0), n ∈ {10, 40} 의 D0[l*] − P0(L1 의 n ≤ 40 범위), 3지역 보조 열(2순위를 돌렸을 때), 학습기별 `sel_default` 대상 수 |
| LGF-N2 (조정 효과) | 조정판과 기본판의 차이는 동등성 한계 안이다 | 학습기마다 R1[l*] − R1[l](λ 0.25 와 1.0)과 D0[l*] − D0[l](λ 1.0)을 n ∈ {0, 10, 전량} 에서 본다. 모두 동등이면 '초모수 선택에 강건(한계 0.5 cm)'. 우세만 있으면 '조정판의 오차가 작다(대비, n, 크기)'이고 그 조정판을 L5·L26 의 학습기 비교 표에 병기한다. 열세만 있으면 '원천 교차검증 조정이 전이 오차를 키웠다(대비, n, 크기)'. 우세와 열세가 함께 있으면 '혼재'. 그 밖은 '차이를 확인하지 못함'. 2.2 의 λ 조합 규칙을 쓴다. n ∈ {40, 160} 은 보조다. 문장 '신경망의 결론은 초모수 선택에 강건하다'는 네 학습기가 모두 '강건'일 때만 쓴다 |
| LGF-N3 (CatBoost 대비) | 조정판과 CatBoost 의 R1 차이는 동등성 한계 안이다 | L26 과 같은 형식이다. R1[l*] − R1[CB] 를 n ∈ {0, 10, 전량} 에서 본다. 모두 동등(λ 0.25 와 1.0)이면 '동등(한계 0.5 cm)', 우세와 열세가 없고 미결정이 있으면 '차이를 확인하지 못함', 우세·열세는 표로 보고한다. 로컬 기본판의 R1[l] − R1[CB] 와 D0 의 같은 대비를 보조로 병기한다 |
| LGF-N4 (서술) | 없음 | 선택 표, 원천 교차검증에서 선택 설정과 시도 0 의 점수 차, 보조 기준에서의 선택 안정성, `sel_default` 수, 원천 교차검증 점수 차와 대상 Δ(l* − l, n = 0)의 관계(점 (학습기, 종류, 대상) 32개의 순위 상관, 검정 없음), 설정별 적합 시간 |

**판정 세부 규칙(N)**

| 항목 | 규칙 |
|---|---|
| 풀 | 2.2 와 같다 |
| 판정할 수 없는 대비 | N1 은 확인적 규칙(6A.5a)을 따른다. 네 학습기 대비 가운데 4분 판정이 나온 대비가 k < 4 이면 지지 문구를 쓰지 않는다. 판정이 나온 대비에 우세가 있으면 '기각(일부 대비 판정 불가, 대비 k/4)', 아니면 '판정 불가(대비 k/4; 없는 대비: …)'. N2, N3 은 k < m 이면 판정 불가이되 판정이 나온 대비의 우세·열세는 보고하고 '부분(대비 k/m)'을 붙인다 |
| 분할 완결성 | N1 은 분할 미완결이면 '판정 불가(분할 k/K)'. N2, N3 은 '부분(분할 k/K): ' |
| 조정판 = 기본판 | 한 학습기·종류에서 네 대상 모두 시도 0 이 선택되면 그 대비는 모든 키에서 Δ = 0 이다. 판정 행에 '조정판 = 기본판(선택 결과)'을 적는다. N1 은 이 경우 로컬 기본판의 대비와 같다 |
| Holm 묶음(보조) | N1 의 4개, N2 의 기준 λ 대비 24개(학습기 4 × n 3 × 방법 2), N3 의 12개를 한 묶음으로 보정한다. N2, N3 의 동등성 p 는 따로 보정한다. 판정에 쓰지 않는다 |
| 교차 환경(보조) | LG 본 실행 결과를 회수한 뒤 로컬 기본판과 LG 조각(Rescale)의 같은 키를 대조해 `lgfn_cross.csv` 에 '교차 환경(보조)'로 적는다. 앞서 P0, P1 이 1e-9 cm 안에서 같은지 확인한다. 플랫폼 차이(하드웨어, torch·numpy 판)가 신경망 적합에 주는 영향의 크기를 서술하는 표이며 판정에 쓰지 않는다 |
| 맹검 표지 | 5절의 표를 따른다 |

### 6.3 실행 순서

1. 구현 뒤 정적 점검(py_compile, pyflakes)과 합성 자료 단위 시험(`tests/test_h47_foundation.py`, `tests/test_h48_nn_tuning.py`).
2. `--count-only`(스레드 1): 작업 단위, 적합 수, fold 구성, 설정 목록(`lgfn_configs.json`)을 확정하고 개정 이력에 적는다.
3. 스모크(10분 이내): h47 은 GPU 4 에서 Russia_W x·Canada x, 분할 1, n {0, 10, 40, 전량}, 추출 1, seed 1, 주 설정과 full. h48 은 GPU 3 에서 Canada x, 분할 1, n {0, 10}, 추출 1, seed 1, 학습기 4종(epoch 3). 스모크 집계는 곡선과 판정 표를 쓰지 않고 Δ 와 판정을 화면에 내지 않는다(LG 6C 개정 12 와 같다). 경로 점검(ctx_sha 가 h43 의 구성과 같은지, n = 0 의 R1 = R0, 가중치 캐시 하위 클래스와 원래 클래스의 예측 차, 묶음 예측 차, 조정판 학습 행이 h40 의 학습 행과 같은지)과 시간만 낸다.
4. 사전 점검(시간 측정, 판정 없음): h47 은 GPU 4 에서 레나 x 와 Alaska x 의 분할 1, n {0, 40, 전량}, 추출 0, seed 0(약 30분). h48 은 GPU 3·2 에서 학습기마다 시도 0 과 무작위 설정 3개의 fold 적합(레나 x)과 기본판 본 적합 1단위(약 1–2 h). 결과로 8.3 의 환산을 다시 계산하고 8.4 의 축소 규칙을 적용해 개정 이력에 적는다. 이 개정은 본 실행 전, 결과 열람 전이다.
5. 본 실행. F 는 GPU 4 에서 3.5 의 순서로 돈다. N 은 GPU 3·2 에서 우선순위 큐로 돈다: 선택 1단계(학습기 순서 MLP, TabM, FT-T, RealMLP, 대상 순서 주 4지역 다음 Alaska x) → 선택 2단계 → 선택 표 → 통과 0 → `catboost_lo` → 통과 1(분할 번호 순, 빠른 학습기 먼저) → 2순위. 한 학습기·대상의 본 적합 단위는 그 학습기·대상의 선택이 끝난 뒤에만 큐에 들어간다.
6. F 가 끝나 GPU 4 가 비면 N 을 멈추고(SIGTERM) `--gpus 4,3,2 --resume` 으로 다시 시작해 남은 단위를 나눈다.
7. 집계(`--summarize-only`, 스레드 2, GPU 없음). F 는 LGT 조각이 있으면 3.4 의 조건으로 짝을 병합한다. LGT 가 끝나기 전의 집계는 분할 완결성 규칙으로 표시한다.

## 8. 시간 추정과 축소 규칙

### 8.1 예산

B = GPU 3장(4, 3, 2) × 24 h = 72 GPU-h 다. GPU 2 를 쓸 수 없으면 B = 48 GPU-h 다. Rescale 비용은 0 이다. CPU 는 LGF 프로세스 안의 CatBoost 와 전처리뿐이다(프로세스당 2스레드).

### 8.2 F 추정

TabICL 적합 1건의 시간은 재지 않았다. LGT 의 TabPFN 추정식 t_T = 0.5 + (6.7 + 0.6 × 채점 행 수/1,000) × (컨텍스트 행 수/9,900) s 에 배율 r ∈ [0.5, 1.5](기준 1.0)을 곱한다고 가정했다. 근거는 합성 자료 점검(500행 적합 1.22 s)뿐이다. full 은 컨텍스트가 1.4–1.8배라 선형 가정의 값에 2배까지의 여유를 두었다(어텐션 계산량은 컨텍스트 행 수의 제곱에 가깝게 늘 수 있다). CatBoost 는 LGT 의 4스레드 추정에 1.5를 곱해 2스레드로 환산했다.

| 범위 | TabICL 적합 | TabICL GPU-h(기준, 범위) | catboost_ctx h(2스레드) |
|---|---|---|---|
| 1순위 | 2,450 | 4.8 (2.4–7.2) | 0.4 |
| 2순위 | 4,730 | 6.4 (3.2–9.6) | 0.5 |
| full | 480 | 1.7 (0.8–5.0) | 0.1 |
| 기본 범위 합계(GPU 4 의 벽시계) | 7,660 | 12.9 (6.4–21.8) | 1.0 |
| 3순위(예산 조건부) | 9,620 | 17.3 (8.6–25.9) | 1.4 |

기본 범위의 벽시계는 기준 약 14 h, 범위 7.4–22.8 h 다.

### 8.3 N 추정

적합 1건의 시간은 RTX 3090 1장, 프로세스 1개, 학습 행 약 15,000을 가정한 값이다. 기본판은 T4 사전 점검 실측(D0·R1: MLP 2.31·1.25 s, TabM 2.54·1.86 s, FT-T 61.9·59.1 s, RealMLP 256 epoch 환산 134·93 s)을 2–3배 빠르다고 보고 환산했다. 이 배율은 재지 않았다. 조정판의 적합 시간은 재지 않은 가정값이다(배치 256–2,048 과 patience 16 때문에 step 수가 기본판의 15–30배가 된다). fold 적합은 전체 적합과 같은 시간으로 두었다(알래스카를 뺀 fold 는 학습 행이 적어 과대 추정이다).

| 학습기 | 1건(기본판) | 1건(조정판) | 선택 fold 적합(1단계 + 2단계) | 선택 GPU-h | 본 적합(판마다) | 기본판 GPU-h | 조정판 GPU-h | 합계 GPU-h |
|---|---|---|---|---|---|---|---|---|
| mlp | 0.9 s | 5 s | 1,056 + 256 | 1.7 | 480 | 0.1 | 0.7 | 2.5 |
| tabm | 1.0 s | 8 s | 1,056 + 256 | 2.7 | 480 | 0.1 | 1.1 | 3.9 |
| ftt | 28 s | 50 s | 576 + 192 | 10.1 | 480 | 3.7 | 6.7 | 20.5 |
| realmlp | 38 s | 45 s | 544 + 192 | 9.0 | 480 | 5.1 | 6.0 | 20.1 |
| 1순위 합계 | | | | 23.5 | | 9.0 | 14.5 | 47.0 |

- 2순위(Alaska x)는 원천 3,860행이라 약 4.5 GPU-h 로 본다(선택 약 1.4, 본 적합 약 3.1. 거친 추정).
- `catboost_lo` 는 640건, CPU 약 0.1 h 다.
- 가정값의 불확실성을 0.6–1.5배로 보면 1순위 합계는 28–71 GPU-h 다.

### 8.4 합계와 축소 규칙(결과 열람 전 고정)

기준 추정의 합계는 F 기본 범위 약 14 GPU-h 와 N 1·2순위 약 51.5 GPU-h 로 약 65.5 GPU-h 다(B = 72 안). F 3순위를 더하면 약 84 GPU-h 로 B 를 넘는다. 벽시계는 F 가 GPU 4 에서 약 14 h, N 이 GPU 3·2 에서 시작해 F 뒤 GPU 4 를 더하면 약 22 h 다.

사전 점검 뒤 측정값으로 기본 범위의 필요 GPU-h P 를 다시 계산한다. P 가 B 를 넘으면 아래 단계를 차례로 적용해 P ≤ B 가 될 때까지 줄인다. 단계의 순서와 내용은 결과와 무관하게 여기서 고정한다.

| 단계 | 줄이는 것 | 기준 추정에서 줄어드는 양 |
|---|---|---|
| S1 | N 2순위(Alaska x) 제외 | 약 4.5 GPU-h |
| S2 | F full 변형 제외 | 약 1.8 GPU-h |
| S3 | F 2순위의 추출 5 → 2(n ∈ {3, 10, 40, 160, 320, 1,000}, 추출 번호 0·1) | 약 3.6 GPU-h |
| S4 | FT-T·RealMLP 의 무작위 설정 16 → 8(고정 목록의 앞 8개. FT-T 시도 1 은 유지) | 약 6.8 GPU-h |
| S5 | N 본 적합의 추출 2 → 1(n ∈ {10, 40, 160}, 추출 번호 0) | 약 7.8 GPU-h |
| S6 | N 통과 1(n > 0)의 분할 1–5 → 1–3. 통과 0(n = 0)은 분할 1–5 를 유지한다 | 약 5–8 GPU-h(S5 적용 여부에 따라) |
| S7 | MLP·TabM 의 무작위 설정 32 → 16 | 약 2 GPU-h |
| S8 | F 2순위 대상을 Alaska x 하나로 줄인다 | 약 2–5 GPU-h(S3 적용 여부에 따라) |

- S8 뒤에도 P > B 이면 더 줄이지 않고 멈춰 사용자에게 보고한다.
- 줄이지 않는 것: F 1순위 전체(F1–F5 의 주 4지역 대비), N 1순위의 선택 단계(S4, S7 의 설정 수 외), N 통과 0(확인적 가설 N1 의 구성 단위).
- F 3순위는 기본 범위가 끝난 시점에 24시간 창에 남은 시간이 3순위의 측정 기반 추정보다 크면 돈다. 아니면 돌지 않고 LGT 의 TabPFN 결과만 해당 대상에 남는다.
- 적용한 단계와 이유(측정값, P, B)를 `lgf_projection.csv` 와 개정 이력에 적는다. 축소한 범위의 판정에는 6A.5a 의 규칙(분할 완결성, 풀 지역 수)을 그대로 쓴다. S5 를 적용하면 N 의 n ∈ {10, 40, 160} 곡선은 추출 1개로 계산된다는 점을 표에 적는다.

### 8.5 확인하지 못한 것

- TabICL 의 적합 1건 시간(컨텍스트 3,860–10,000행, 채점 최대 7,284행)과 GPU 메모리. 컨텍스트 행 수에 대한 시간 의존(선형 가정).
- RTX 3090 과 T4 의 속도비(2–3배 가정), 조정판 설정의 적합 시간.
- CatBoost 의 스레드 수(2와 4)에 따른 재현성.
- LGT 의 진행 속도. F3 과 F4 의 T 병기 열은 LGT 가 끝나야 완결된다.
- 동등성 한계 0.5 cm 의 문헌 근거(LG 6A.2 와 같이 확인하지 못했다).
