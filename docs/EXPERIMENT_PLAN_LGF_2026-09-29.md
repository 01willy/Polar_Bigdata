## 1. 목적

### 1.1 F. 표형 파운데이션 모델 확장

- 심사 질문 '표형 파운데이션 모델을 시험했는가'에 모델 하나(TabPFN v2, LGT)가 아니라 계열로 답한다.
- 공개 가중치 표형 파운데이션 모델 가운데 연구·게재 제약 없이 이 환경에서 쓸 수 있는 모델을 LGT 와 같은 규약(같은 대상, 분할, 라벨 추출, 컨텍스트 규칙)으로 시험한다. 점검 결과 조건을 모두 만족한 모델은 TabICL v2 하나다(3.1).
- 짝 대조군은 두 개다. 같은 컨텍스트 행으로 적합한 CatBoost(`catboost_ctx`, LGF 조각 안에서 다시 적합)와 LGT 의 TabPFN v2(LGT 조각을 읽기 전용으로 짝지음, 3.4)다.

### 1.2 N. 신경망 초모수 강건성

- LG 학습기 축의 신경망 4종(MLP, TabM, FT-Transformer, RealMLP)은 기본 초모수로만 적합했다. 코드를 읽은 결과 MLP·TabM·FT-T 는 배치 8,192, epoch 100, patience 6 이다. 원천 약 15,000행에서는 epoch 당 2 step, 알래스카 계열 대상(원천 3,860행)에서는 1 step 이므로 전체 갱신이 최대 100–200회다. 문헌의 설정(배치 256–1,024, patience 16)과 차이가 크다. 따라서 '신경망이 조정되지 않았다'는 지적에는 실질이 있다.
- 원천 자료 안에서만(대상과 100 km 버퍼 제외, 원천 지역 하나 제외 교차검증) 초모수를 고른 조정판을 만들고 D0·R1 에서 기본판과 짝짓는다. LGX N3(L30, CatBoost 용량과 조정)의 신경망 판이다.
- 기본판은 LG 본 실행(Rescale, T4, torch 2.4.1, numpy 2.4.6)과 하드웨어와 판이 다르다. 그래서 기본판도 로컬에서 같은 조건으로 다시 적합해 조각 안에서 짝을 닫는다.

## 2. 공통 규약

### 2.1 LG·LGX·LGT 와 같게 두는 것

Rescale 조각(LG, LGX)과의 대비는 '교차 환경(보조)'로만 내고 판정에 쓰지 않는다. 2026-09-30 01시 기록의 비교 규칙('지역별 Δ 를 각 플랫폼 안에서 구한 뒤 모은다')은 LGF 에서 이 뜻으로 읽는다 |
| LG 곡선·표와의 관계 | 판정에 따라 LGF 곡선을 LG 마스터 곡선에 더할 때는 플랫폼 표지(로컬 RTX 3090, torch 2.6.0, numpy 1.26.4)를 붙이고, 같은 로컬 조각의 비교 곡선(F 는 `catboost_ctx`, N 은 로컬 기본판과 `catboost_lo`)을 함께 넣는다. L5·L26 의 학습기 비교 표에는 병기하지 않고 LGF 의 N3 표로 따로 보고한다. 병기가 필요하면 '교차 환경(보조)' 열로 분리하고, 두 플랫폼 값 사이의 차는 계산하거나 서술하지 않는다. 표마다 정본 플랫폼을 정하는 규칙은 LG 계획서의 개정 후보로 적어 둔다(이 문서는 LG 계획서를 고치지 않는다) |
| Holm 묶음 | 확인적 대비와 보조 대비는 다른 묶음으로 보정한다(3.6, 4.5). 보조 묶음에서 보정 뒤 p ≥ 0.05 인 우세·열세에는 '보정 전 유의'를 붙인다. 판정은 바꾸지 않는다 |
| 효과 크기 | 우세 또는 열세이면서 점 추정 절댓값이 0.5 cm 미만이면 '통계적으로 구별되나 크기는 0.5 cm 미만'을 붙인다 |
| 실패 처리 | 비유한 예측이 있는 키는 저장하지 않고 실패 표(`lgf_failed.csv`, `lgfn_failed.csv`)에 남긴다. 짝의 한쪽이 없는 키는 위 짝 키 규칙으로 대비에서 빠진다 |

### 2.3 F 가 LGT(6C.2–6C.4)를 그대로 따르는 것

- 방법 P0, P1, D0, R0, R1 의 정의(6C.3 의 표). n = 0 에서 R1 은 R0 과 같은 적합을 쓴다. 세 방법은 같은 (n, 추출, seed)에서 같은 컨텍스트 행을 쓰고 목표만 다르다.
- 컨텍스트 규칙(6C.4) 전부: 상한 C = 10,000행, 대상 라벨 행 1배(부분 추출 없음), 원천 예산 m = min(원천 행 수, C − max(T, 1,000)), 지역 비례 층화 중첩 부분 추출, 부분 추출이 없는 대상(원천 3,860–3,861행), 큰 n 의 규칙, T > 9,000 의 규칙, 행 순서(원천 행 다음 대상 행), 채점 셀 한 번 예측과 CUDA 메모리 부족 때의 4,096행 묶음 재예측.
- 부분 추출 seed 는 LGT 의 문자열을 그대로 쓴다: seed_of('lgt-ctx', 대상, 모드, 분할, 학습기 seed). 이름을 바꾸면 TabPFN 과 같은 행이 되지 않는다.
- 구현은 h43 의 컨텍스트 함수(`ctx_order`, `src_budget`, `context_rows`, `build_X`, `build_y`, `coef_n`, `ctx_sha`)를 importlib 로 불러 그대로 쓴다. 새로 구현하지 않는다.
- `catboost_ctx` 의 정의(반복 200, 학습률 0.05, 깊이 3, l2 3, random_seed = 학습기 seed, 입력 x25 원값, 학습과 채점 Pool 의 thread_count 지정. h43 의 `cb_fit_predict`).
- 주 설정의 범위: n 전 격자 {0, 3, 10, 40, 160, 320, 1,000, 전량}(\|A\| 미만과 전량), 추출 5, seed 2, 대상 27 과 그 실행 순서.

### 2.4 F 가 LGT 와 다르게 두는 것

| 항목 | LGT | LGF-F |
|---|---|---|
| 새 학습기 | `tabpfn`(TabPFN v2) | `tabicl`(TabICL v2) |
| 입력의 결측 | NaN 을 그대로 넘기고 TabPFN 이 처리한다 | pandas DataFrame 으로 넘긴다. TabICL 2.0.2 의 전처리(`TransformToNumerical`)가 수치 열의 결측을 SimpleImputer(평균, 컨텍스트 행으로 적합)로 채운다. 결측 지시자는 만들지 않는다. 2.0.2 는 numpy 배열의 NaN 을 받지 않는다 |
| 열 종류 | 컨텍스트가 100행을 넘으면 `cci_valid` 를 범주형으로 추론한다(6C 개정 12) | `TransformToNumerical` 은 수치 자료형 열을 연속형으로 다룬다(설치된 소스 확인). 그 뒤의 열 처리(상수 열 제거, 이상치 처리, 멱변환 앙상블)는 2.0.2 의 기본값이다 |
| TabPFN 값 | 조각 안에서 적합 | LGT 조각을 읽기 전용으로 짝짓는다(3.4) |
| `catboost_ctx` | LGT 조각 안에서 적합 | LGF 조각 안에서 다시 적합한다(같은 정의, 같은 컨텍스트 행) |
| 민감도 | d3, d10, rid, tgt | full(원천 전체를 컨텍스트로, 3.3) 하나 |
| GPU | 9·7·6 | 6.1 의 후보 가운데 실행 시점에 빈 GPU |
| 실행 파이썬 | 전역 python3 | `.venv_lgf/bin/python`(같은 torch·numpy·pandas·scikit-learn·catboost 판에 tabicl 추가) |

입력 처리의 두 차이(결측 대치, 열 종류)는 학습기 정의의 일부로 둔다. 두 모델의 기본 사용법을 바꾸지 않기 위해서다. F3 의 해석에 이 차이를 적는다.

결측은 주 4지역에 몰려 있다. 심사 단계의 계산(`load_base`, 스레드 1. 이 문서에서 다시 계산하지 않았다)으로 x25 가운데 하나라도 결측인 행의 비율은 레나 13.1 %, 러시아 W 9.7 %, 러시아 E 10.0 %, 캐나다 0.5 %, 알래스카 0 % 다(결측 열은 토양 9열과 `cci_alt`). TabICL 은 이 셀의 결측을 컨텍스트 평균(알래스카 비중이 큰 값)으로 채운다. 그래서 F2·F3 의 Δ 를 채점 셀의 결측 유무(x25 가운데 하나라도 결측)로 나눈 서술 표(`lgf_missing_desc.csv`: 대비, n, 부분집합, 셀 수, 점 추정. 판정과 CI 없음)를 등록한다. 부분집합의 셀 수가 30 미만인 지역은 점 추정을 비워 둔다.

### 2.5 N 의 학습 규약

- 학습 행은 LG 학습기 축과 같다. 원천 전체 ∪ 대상 라벨 n개이고 가중이 없다. 컨텍스트 상한은 없다.
- 입력 전처리, 목표 척도, 조기 종료 검증은 기본판이 LG 의 코드 경로 그대로다(4.1). 조정판의 전처리는 4.2 의 공간 안에서 고르며 통계는 학습 행으로만 구한다.
- 대상, n 격자, 추출, seed, 분할, 방법은 4.4 에 적는다.

**tabicl 판 고정**: 2.0.2 로 고정한 이유는 Python 3.9 를 지원하는 마지막 판이기 때문이다. 본 실행 전(6.3 단계 5)에 2.0.3 이후 판의 변경 기록에서 결측 처리와 전처리의 변경 여부를 확인해 개정 이력에 적는다. 이 문서 작성 시점에는 확인하지 않았다.

### 3.2 학습기 정의

| 학습기 | 설정 |
|---|---|
| `tabicl` | `TabICLRegressor(n_estimators=8, norm_methods=None(= none, power), feat_shuffle_method='latin', outlier_threshold=4.0, batch_size=8, model_path=<3.1 의 절대 경로>, allow_auto_download=False, checkpoint_version='tabicl-regressor-v2-20260212.ckpt', device='cuda', use_amp='auto', use_fa3='auto', offload_mode='auto', random_state=<학습기 seed>, n_jobs=None, verbose=False, inference_config=None)`. fit 의 `kv_cache=False`. 모두 2.0.2 의 기본값이고 바꾼 것은 가중치 경로, 자동 내려받기 금지, 장치, random_state 뿐이다. 입력은 x25 원값을 열 이름이 있는 DataFrame(float32, 결측은 NaN)으로 넘긴다. 예측은 `predict(X, output_type='mean')` 이다. 초모수 조정과 미세 조정은 하지 않는다 |
| `catboost_ctx` | LGT 와 같다(2.3). 같은 프로세스에서 TabICL 과 같은 컨텍스트 행렬과 목표로 적합한다 |
| `tabpfn` | LGF 는 적합하지 않는다. LGT 조각의 키를 3.4 의 조건으로 읽어 짝짓는다 |

구현 규약:
- `use_amp='auto'` 는 컨텍스트가 1,024행 이상이거나 특징이 60개 이상이면 혼합 정밀도를 켠다. F 의 컨텍스트는 모두 3,860행 이상이므로 모든 적합에서 켜진다. FA3 는 `.venv_lgf` 에 `flash_attn_interface` 가 없어(`importlib.util.find_spec` 으로 확인) 쓰이지 않는다. full 변형처럼 전체 행이 10,240 이상이면 `use_fa3='auto'` 가 True 로 결정되지만, `tabicl.model.attention.HAS_FLASH_ATTN3` 가 False 이므로 실제로는 쓰이지 않는다. 조각에는 결정된 플래그가 아니라 `HAS_FLASH_ATTN3` 값과 AMP, offload 방식의 실제 적용 값을 적는다.
- 스레드: `n_jobs=None` 을 유지한다. 2.0.2 의 `predict` 는 `n_jobs > 0` 이면 torch 스레드를 max(논리 코어 수, n_jobs)로 올린다(설치된 소스에서 확인). 준비 단계 기록에는 2.2.0 에서 고쳐졌다고 되어 있으나 이 문서에서는 확인하지 않았다. 스레드는 `torch.set_num_threads(2)` 와 OMP·MKL·OpenBLAS·NUMEXPR 환경 변수로 제한한다.
- 가중치 적재: 2.0.2 의 `fit` 은 적합마다 체크포인트를 `torch.load` 로 다시 읽는다. 하네스는 워커마다 체크포인트 사전(config, state_dict)을 한 번 읽어 두고 적합마다 그 사전으로 모델을 만든다(`_load_model` 만 바꾼 하위 클래스). 가중치와 계산은 같다. 스모크에서 원래 클래스와의 예측 차(최댓값)가 1e-6 cm 이하인지 확인하고, 넘으면 원래 클래스를 쓴다.
- 입력 형식: 적합, 예측, 묶음 재예측에는 항상 같은 열 이름(`h40.FEATS`, 25열)의 DataFrame(float32, 결측은 NaN)을 넘긴다.
- 시간 기록: 적합 1건의 시간(`fit_s`)은 `fit` 과 `predict` 호출 전체다. 적합마다 하는 CPU 전처리(Yeo-Johnson 변환 등)가 들어간다.
- 체크포인트의 SHA-1 이 3.1 의 값과 다르면 실행하지 않는다. `HF_HUB_OFFLINE=1` 을 둔다.
- h43 의 SHA-1 이 13148bb899e92c49ba24f2f9cb6463e56da26a2a(커밋 45ef3b6, LGT 본 실행의 판)와 다르면 실행을 거부한다. 바뀐 h43 을 쓰려면 개정으로 등록하고 `--h43-sha` 인자로 새 값을 준다. 컨텍스트 구성이 바뀌면 3.4 의 ctx_sha 조건이 짝을 막는다.
- `SimpleImputer` 는 컨텍스트에서 모두 결측인 열을 버린다(scikit-learn 1.3.0 의 기본). 등록 범위에서 이런 열이 생기는지 `--count-only --dry-build` 로 확인하고 수를 적는다.

### 3.3 방법

| id | 컨텍스트 행의 목표 | 예측 | 기준 λ |
|---|---|---|---|
| P0, P1 | 해석식 | E0·s, E_n·s. 모든 조각에 저장한다 | 없음 |
| D0 | 원천 행 y, 대상 라벨 행 y | f(x) | 1.0 |
| R0 | 원천 행 y − E0·s, 대상 라벨 행 y − E0·s | E0·s + λ·g(x) | 0.25 |
| R1 | 원천 행 y − E0·s, 대상 라벨 행 y − E_n·s | E_n·s + λ·g(x) | 0.25 |
| D0@full, R1@full | D0, R1 과 같다 | D0, R1 과 같다 | 1.0, 0.25 |

**full 변형**: 컨텍스트 상한을 두지 않는다. 원천 행 전부(`ctx_order` 의 순서)와 대상 라벨 행(1배)을 넣는다. 학습기는 `tabicl` 과 `catboost_ctx` 다. full 의 `catboost_ctx` 는 원천 전체 ∪ 대상 라벨로 학습하므로 LG 의 `catboost_lo` 와 같은 정의다(로컬에서 적합). 목적은 TabPFN 의 사전 학습 범위에서 정한 상한 10,000행이 TabICL 의 결과를 제한했는지 보는 것이다. R1@full 의 n = 0 은 R 목표의 적합(E_n = E0)이다. n = 0 의 D0@full 은 확인적 가설 F1 의 판정 대비 가운데 하나다(3.6).

### 3.4 TabPFN v2 와의 짝(LGT 조각 읽기 전용)

LGF 조각과 LGT 조각의 짝은 같은 컨텍스트 행일 때만 성립한다. 작업 단위(대상, 모드, 분할)마다 다음 조건을 모두 확인한다.

| 조건 | 내용 |
|---|---|
| 1. 조각 상태 | LGT 조각(`data/processed/lgt/shards/lgt__gpu__<대상>__<모드>__s<분할>_*`)의 `unit.json` 이 있고 status 가 ok 또는 partial 이다 |
| 2. 설정 | LGT 조각의 설정에서 컨텍스트 매개변수(ctx_max 10,000, ctx_reserve 1,000, ctx_src_min 1,000, 중복 배수 1, κ 10, seed 2, 추출 5, n 격자)와 하위 지역 대응표 이름이 LGF 와 같다 |
| 3. 물리식 | P0, P1 키의 셀 가중 RMSE 가 1e-9 cm 안에서 같다 |
| 4. 컨텍스트 해시 | 같은 (방법, n, 추출, seed)에서 LGT 의 `tabpfn` 행과 LGF 의 `tabicl` 행의 `ctx_sha`(컨텍스트 행렬 float32 와 목표 float64 의 SHA-1 앞 12자, h43 의 `ctx_sha`)가 같다. 한 키라도 다르면 그 단위의 TabPFN 키 전부를 짝에서 뺀다. LGT 에 없는 키는 짝 키 규칙(2.2)으로 빠진다 |
| 5. 채점 블록 | 두 조각의 채점 블록 집합과 블록별 셀 수가 같다(`BlockStore.merge` 의 확인) |

- 조건을 모두 통과한 단위의 `tabpfn` 키(LGT 주 설정 `ctx_set = main` 의 키만)를 LGF 집계의 BlockStore 에 병합한다. 단위별 통과 여부와 사유는 `lgf_gate.csv` 에 남긴다.
- 보조 점검: LGF 의 `catboost_ctx` 와 LGT 의 `catboost_ctx` 를 키별 셀 가중 RMSE 로 대조한다(허용 차 0.02 cm). 어긋나도 짝에서 빼지 않고 표시만 한다. 두 실행의 스레드 수가 다르면 그 값을 함께 적는다(CatBoost 의 스레드 수에 따른 재현성은 확인하지 못했다).
- h43 의 코드 해시: LGF 조각에 기록한 h43 SHA-1 과 LGT 조각의 `code_sha` 가 다르면 경고한다. 짝의 판단은 조건 4 로 한다.
- 두 적합은 같은 서버, 같은 GPU 기종(RTX 3090), 같은 torch·numpy·pandas·scikit-learn·catboost 판에서 돈다. 프로세스와 GPU 번호만 다르므로 같은 플랫폼으로 본다.
- LGT 결과가 없거나 조건을 통과한 단위가 없으면 TabPFN 을 쓰는 대비(F3, F4 의 병기 열)는 '행 없음'이다. 다른 가설의 판정에는 영향이 없다.

### 3.5 범위와 적합 수

적합 수는 LGT 의 `--count-only` 표(`lgt_count.csv`)의 값이다. LGF 는 같은 컨텍스트 규칙을 쓰므로 TabICL 적합 수는 TabPFN 적합 수와 같다. 구현 뒤 h47 의 `--count-only` 로 다시 확인한다. 작업 단위는 (축, 대상, 모드, 분할, 부분)이고 부분은 `n0`(n = 0)과 `pos`(n > 0)다. 확인적 가설 F1 의 구성 단위(`n0`)를 먼저 채우기 위해 나눈다. 같은 (대상, 모드, 분할)의 두 부분은 집계에서 BlockStore 로 합친다.

| 범위 | 작업(8.4) | 대상 | 분할 | n | 추출 × seed | 방법 | TabICL 적합 | catboost_ctx 적합 |
|---|---|---|---|---|---|---|---|---|
| 1순위 n = 0(`lgf`, `lgfs`) | J1 | 주 4지역 x | 1–5 | 0 | 1 × 2 | D0, R0(= R1), D0@full, R1@full | 160(주 80, full 80) | 160 |
| 1순위 n > 0(`lgf`) | J6 | 주 4지역 x | 1–5 | 전 격자의 n > 0 | 5 × 2 | D0, R0, R1 | 2,370 | 2,370 |
| full n > 0(`lgfs`) | J8 | 주 4지역 x | 1–5 | {10, 40, 160, 전량} | 2 × 2 | D0@full, R1@full | 400 | 400 |
| 2순위 Alaska x(`lgf`) | J9 | Alaska x | 1–5 | 전 격자 | 5 × 2 | D0, R0, R1 | 950 | 950 |
| 2순위 나머지(`lgf`) | J11 | Russia_C x, Greenland x, AL-1–AL-3 x, CA-2 x, CA-3 x(7대상) | 1–5 | 전 격자 | 5 × 2 | D0, R0, R1 | 3,780 | 3,780 |

- 기본 범위는 J1, J6, J8, J9, J11 이다(1순위, full, 2순위). 3순위(J12)는 8.4 의 창 규칙으로만 돈다. 이 규칙은 결과와 무관하게 정한다.
- 분할의 실행 규칙은 LG 와 같다(중복 분할과 무효 분할은 실행하지 않는다. 그린란드만 무효 분할로 점 추정을 낸다). 주 4지역의 분할 5개는 모두 유효하다.
- 실행 순서는 8.4 의 단일 큐(J1–J12)를 따른다. 묶음 안에서는 대상 순서(주 4지역: 레나, 캐나다, 러시아 W, 러시아 E), 분할 번호 순이다.

### 3.6 가설과 판정(결과 열람 전 고정)

I = `tabicl`, C = `catboost_ctx`, T = `tabpfn`(LGT 조각). D0@full, R1@full 은 full 변형의 방법이다. 모든 대비는 기준 λ 와 4분 판정을 쓰고, 따로 적지 않으면 주 4지역 층화 평균이다.

| id | 가설 | 판정 |
|---|---|---|
| LGF-F1 (라벨 0 직접 예측, 확인적) | 라벨 0 에서 TabICL 직접 예측(D0)은 원천 계수 물리식(P0)을 넘지 못한다. 컨텍스트 상한 10,000행과 원천 전체의 두 조건에서 본다 | 판정 대비는 n = 0 의 D0[I] − P0 와 D0@full[I] − P0(모두 λ 1.0) 두 개다. 둘 다 우세가 아니면 지지, 하나라도 우세이면 기각이다. 지지는 2.2 의 두 갈래로 적는다. 두 대비가 모두 열세 또는 동등이면 '지지(물리식보다 오차가 크거나 구별되지 않음)'이고 문장은 '표형 파운데이션 모델 TabICL v2 를 학습기로 써도(컨텍스트 상한 10,000행과 원천 전체의 두 조건) 직접 ML 은 라벨 0 전이에서 원천 계수 물리식을 넘지 못한다'다. 미결정이 하나라도 있으면 '지지(우세 근거 없음, CI [a, b] cm)'이고 문장은 '라벨 0 전이에서 TabICL v2 직접 ML 이 원천 계수 물리식보다 낫다는 근거는 관찰되지 않았다(두 조건)'다. 기각이면 L1 의 라벨 0 부분 결론을 'TabICL 을 제외한 학습기 한정'으로 적고, TabICL 의 D0 곡선을 플랫폼 표지와 로컬 D0[C] 곡선과 함께 마스터 곡선에 더한다(2.2). 병기: 지역 행, 3지역 보조 열, D0[C] − P0, D0@full[C] − P0. 보조 행(판정에 쓰지 않음): (a) n ∈ {3, 10, 40} 의 D0[I] − P0 층화 평균, (b) L1 형식의 지역 수(주 4지역 가운데 n ∈ {0, 3, 10, 40} 의 어느 n 에서든 D0[I] − P0 의 지역 블록 CI 상한 < 0 인 지역의 수) |
| LGF-F2 (학습기 동등성) | R1 에서 TabICL 과 같은 컨텍스트 CatBoost 의 차이는 동등성 한계 안이다 | L32 와 같은 형식이다. R1[I] − R1[C] 를 n ∈ {0, 10, 40, 160, 전량} 에서 본다. 다섯 n 모두 동등(λ 0.25 와 1.0)이면 '동등(한계 0.5 cm)'. 우세와 열세가 없고 미결정이 있으면 '차이를 확인하지 못함'이고 2.2 의 정밀도 표기를 붙인다. 우세 또는 열세인 n 이 있으면(기준 λ 0.25 로 판정) n, 방향, 크기를 표로 보고하고 λ 1.0 의 대비를 병기한다. 2.2 의 λ 조합 규칙과 보조 한계 병기를 쓴다. n ∈ {3, 320, 1,000} 과 D0, R0 의 같은 대비는 보조다 |

R1[I] − R1[T] 를 n ∈ {0, 10, 40, 160, 전량} 에서, D0[I] − D0[T] 를 n = 0 에서 본다(여섯 대비). 여섯 대비 모두 동등이면 'TabICL v2 와 TabPFN v2 의 차이는 한계 0.5 cm 안이다'. 우세 또는 열세인 대비가 있으면 대비, n, 방향, 크기를 보고한다. 그 밖은 '두 모델의 차이를 확인하지 못함'이고 2.2 의 정밀도 표기를 붙인다. 보조 한계를 병기한다. 두 모델의 차이에는 입력 처리의 차이(2.4 의 결측 대치와 열 종류)가 포함된다는 점을 판정 행에 적고, 결측 서술 표(2.4)를 함께 낸다. T 열의 맹검 표지는 5절을 따른다 |
| LGF-F4 (순가치와 전량) | TabICL 잔차(R1)는 같은 라벨로 재보정한 물리식(P1)을 넘는다 | L33 과 같은 형식이다. R1[I] − P1 을 n ∈ {3, 10, 40, 160, 320, 전량} 에서 보고 우세인 최소 n 을 4지역 평균인 n 과 2–3지역 평균인 n 으로 나눠 보고한다. n ≤ 40 에서 우세이면 '희소 라벨에서도 TabICL 잔차의 순가치가 있다'. 어느 n 에서도 우세가 아니면 'TabICL 잔차의 재보정 물리식 대비 순가치는 확인되지 않았다'. 열세인 n 은 표로 보고한다. R1[C] − P1 과 R1[T] − P1(짝 조건 통과 단위)을 병기한다. 추가 행: 전량의 R1[I] − P0(L35 형식). 우세이면 '라벨 전량에서 TabICL 잔차는 원천 계수 물리식을 넘는다'. 보조 행(판정에 쓰지 않음, 추가 적합 없음): 전량의 R1@full[I] − P0 |
| LGF-F5 (라벨 0 잔차, 방향 중립) | 방향을 정하지 않는다 | n = 0 의 R0[I] − P0 의 4분 판정을 보고한다(L34(b) 형식). 우세 '라벨 0 에서 TabICL 잔차는 원천 계수 물리식보다 오차가 작다', 열세 '오차가 크다', 동등 '구별되지 않는다(한계 0.5 cm)', 미결정 '차이를 확인하지 못함'. R0[C] − P0 를 병기한다. 보조 행(판정에 쓰지 않음): n = 0 의 R1@full[I] − P0(λ 0.25. 원천 전체 조건의 R0 에 해당한다) |
| LGF-F6 (컨텍스트 상한, 방향 중립) | 방향을 정하지 않는다 | R1@full[I] − R1[I], D0@full[I] − D0[I] 를 n ∈ {0, 10, 전량} 에서 본다(공통 추출 0, 1 로 짝짓는다). 모두 동등이면 '컨텍스트 상한 10,000행의 영향은 한계 0.5 cm 안이다(TabICL)'. R1@full[I] − R1[I] 가 우세인 n 이 있으면 '원천 전체를 컨텍스트로 주면 TabICL 잔차의 오차가 줄어든다(n)', 열세이면 '늘어난다(n)'. 그 밖은 n 별로 서술하고 2.2 의 정밀도 표기를 붙인다. 보조 한계를 병기한다. R1@full[I] − R1@full[C] 를 병기한다(원천 전체 조건의 학습기 대비) |

| 계열 문장 | '표형 파운데이션 모델 2종(TabPFN v2, TabICL v2)'을 주어로 한 문장은 두 모델의 같은 형식 판정이 같을 때만 쓴다. 라벨 0 직접 예측은 F1 이 '지지(물리식보다 오차가 크거나 구별되지 않음)'이고 LGT L34(a)의 D0[T] − P0 4분 판정이 열세 또는 동등일 때다. 학습기 동등성은 F2 와 L32 가 모두 '동등'일 때다. 다르면 모델별로 쓴다. 시험하지 않은 모델로 일반화하지 않는다. 결과 열람 뒤에 더한 모델은 넣지 않는다(3.1) |
| L1 과의 관계 | F1 이 고칠 수 있는 범위는 L1 의 라벨 0 부분이다. F1 이 기각이면 L1 의 라벨 0 결론에 한정어를 붙인다(위 표). F1 이 '지지(물리식보다 오차가 크거나 구별되지 않음)'이면 L1, L30, LGT L34(a)와 함께 라벨 0 부분의 '학습기 종류와 무관' 근거 목록에 TabICL 을 더한다. '지지(우세 근거 없음)'이면 목록에 더하지 않는다. 보조 행 (b)에서 우세 지역이 2개 이상이면 F1 의 판정과 별도로 L1 결론에 'TabICL v2 는 n ≤ 40 에서 예외(지역, n)'를 적고, 이때는 F1 이 지지여도 TabICL 을 L1 의 n ≤ 40 전체 근거로 쓰지 않는다. 보조 행 (a)에 우세인 n 이 있으면 그 n 을 L1 결론의 한계로 적는다 |
| Holm 묶음(보조 열) | 확인적 묶음: F1 의 2개. 보조 묶음: F2 의 기준 λ 5개, F3 의 6개, F4 의 6개와 전량 R1[I] − P0 1개, F5 의 1개, F6 의 6개(R1@full − R1 과 D0@full − D0, n 3개씩), F4·F5 의 @full 보조 행 2개로 27개다. 양측 부트스트랩 p 를 보정한다. F2, F3, F6 의 동등성 p 는 따로 한 묶음으로 보정한다. 판정에 쓰지 않는다. 보조 묶음에서 보정 뒤 p ≥ 0.05 인 우세·열세에는 '보정 전 유의'를 붙인다 |
| 결측 서술 | 2.4 의 `lgf_missing_desc.csv`(F2·F3, 판정 없음) |
| 맹검 표지 | 5절의 표를 따른다 |

## 4. N: 신경망 초모수 강건성

### 4.1 학습기와 기본판

기본판은 LG 의 코드 경로를 그대로 부른다(h40 의 `run_ctx` 와 `Fitter`). 아래 값은 코드를 읽어 확인한 것이다.

| 학습기 | 코드 경로 | 기본 설정 |
|---|---|---|
| `mlp` | `h40.mlp_fit`(`tab_models._torch_mods` 의 MLP, `tab_models._epochs_fit`) | 25→256→128→64→1, 앞 두 층 ReLU·BatchNorm·Dropout 0.1. Adam lr 1e-3, weight_decay 1e-5, SmoothL1(학습 행의 평균·SD 로 z 변환한 y), 배치 8,192, epoch 100, 학습 행 무작위 10 % 검증의 MSE 로 조기 종료(patience 6, 최소 개선 1e-4, 최적 상태 복원), 기울기 절단 5. 입력은 학습 행렬의 중앙값 대체와 표준화(`h40._prep_stats`) |
| `tabm` | `m1_core.fit_model` → `tab_models._fit_torch('tabm')` | 공유 몸통 25→256(ReLU·BatchNorm·Dropout 0.1)→128(ReLU·BatchNorm)과 독립 헤드 k = 8개(128→64→1), 헤드 출력 평균. Gorishniy 2025 의 TabM(BatchEnsemble 어댑터)이 아니라 다중 헤드 MLP 다. 학습 규약은 `mlp` 와 같다 |
| `ftt` | `m1_core.fit_model` → `tab_models._fit_torch('ftt')` | 수치 특성마다 선형 토큰화와 CLS 토큰, d = 64, head 8, 블록 3, FFN 128, GELU, pre-norm, dropout 0.1 하나(attention·FFN·잔차 공통), 출력 LayerNorm + Linear. Adam lr 5e-4, 그 밖의 학습 규약은 `mlp` 와 같다. 원 논문 기본값(d 192, ReGLU, FFN 비 4/3, dropout 3종 분리, AdamW lr 1e-4)보다 작다 |
| `realmlp` | `h40.realmlp_fit_predict`(pytabkit 1.7.3 `RealMLP_TD_Regressor`) | TD 기본값(은닉 [256]×3, pbld 수치 임베딩, front scale, dropout 0.15 flat_cos, wd 0.02 flat_cos, lr 0.2 coslog4, Adam β2 0.95, 배치 256, epoch 256, 무작위 20 % 검증으로 최적 epoch 선택). 입력은 h40 이 표준화한 x25. 이미 문헌 기본값으로 돌았다 |

원고에서는 `tabm` 과 `ftt` 의 구조를 적거나 이름을 바꿔야 한다(9.2).

### 4.2 조정 공간

시도 0 은 모든 학습기에서 현행 기본값이고 4.1 의 코드 경로를 그대로 부른다. 무작위 시도에는 새 하네스 안의 매개변수화 클래스를 쓴다(h40, `tab_models` 는 고치지 않는다). MLP·TabM·FT-T 의 무작위 시도에 공통인 규약은 다음과 같다.

- 최적화기 AdamW, 조기 종료 patience 16(최소 개선 1e-4, 최적 상태 복원), 최대 epoch 300(FT-T 200).
- 검증 분리는 기본판과 같게 학습 행 무작위 10 %(`RandomState(seed).rand(n) < 0.1`), 기울기 절단 5, y 는 학습 행의 평균·SD 로 z 변환한다.
- 입력 변환 {표준화(`h40._prep_stats`), 분위 정규 변환}. 분위 정규 변환은 학습 행 중앙값 대체 뒤 `QuantileTransformer(output_distribution='normal', n_quantiles=min(1000, 학습 행 수), subsample=10**9, random_state=seed_of('lgfn-qt', 학습기, 종류, 시도, 적합 식별자, 학습기 seed) % 2**32)` 를 학습 행으로만 적합한 것이다. scikit-learn 1.3.0 의 기본값(subsample 10,000, random_state None, 설치된 소스 확인)은 원천 학습 행(14,429–17,437)에서 seed 없는 부분 표본으로 분위를 추정해 재현되지 않으므로 쓰지 않는다. 적합 식별자는 선택 단계에서 'sel|대상|모드|제외 지역', 통과 0 에서 'p0|대상|모드', 통과 1 에서 'p1|대상|모드|분할|n|추출'이다. 이 인자들은 설정 해시에 넣는다.
- 손실 {SmoothL1, MSE}.
- 마지막 배치가 1행이면 BatchNorm 이 있는 구성에서 그 1행을 뺀다(`h40.mlp_fit` 과 같은 처리).
- 무작위 시도의 학습 루프는 학습·검증 텐서를 GPU 에 한 번 올리고 배치 색인도 GPU 에서 만든다(`torch.randperm(n, generator=g, device='cuda')`, g 는 학습기 seed 로 초기화). 작은 배치에서 배치마다 CPU→GPU 복사를 하는 `tab_models._epochs_fit` 방식의 비용을 피하기 위해서다. TabM 무작위 시도의 헤드 k 개는 묶음 매개변수(가중치 [k, d, 64], [k, 64, 1]와 편향)와 `torch.einsum` 으로 한 번에 계산한다. 초기화는 헤드마다 `nn.Linear` 기본값과 같은 분포(가중치·편향 모두 U(−1/√fan_in, 1/√fan_in))다. 시도 0 은 원래 코드 경로(4.1)를 그대로 쓴다.

| 학습기 | 설정 수 | 무작위 시도의 공간 | 근거(확인 수준) |
|---|---|---|---|
| `mlp` | 33(시도 0, 무작위 32) | 은닉층 수 UniformInt[1, 6], 폭 64–1,024(16 단위, 로그 균등), 모양 {일정, 층마다 절반(최소 16)}, 정규화 {BatchNorm, 없음}, dropout {0(확률 0.3), U[0, 0.5]}, lr LogU[1e-4, 1e-2], weight_decay {0, LogU[1e-6, 1e-3]}, 배치 {256, 512, 1,024, 2,048} | Gorishniy 2021 표 15(arXiv PDF 직접 읽음), Grinsztajn 2022(arXiv HTML 요약). lr 하한 1e-4 는 최대 300 epoch 안에서 수렴하지 않는 구간을 빼기 위해 올렸다 |

### 4.3 선택 규약

| 항목 | 규칙 |
|---|---|
| 선택 단위 | (대상, 모드) × 학습기 × 종류(D, R)마다 한 번 고른다. 분할, n, 추출마다 고르지 않는다. 원천 집합은 `h40.Data.source_idx(대상, 모드)` 로 정해지고 분할에 의존하지 않기 때문이다. 여러 대상을 묶어 한 설정을 고르는 전역 선택은 쓰지 않는다(대상 T 의 지역이 다른 대상의 원천 fold 로 들어가 T 의 라벨이 선택에 쓰인다) |
| 누설 규약 | 원천 행만 쓴다. 대상 셀과 100 km 버퍼는 `source_idx` 가 이미 뺐다. 대상 라벨, 대상 공변량, 채점 셀은 쓰지 않는다 |
| fold | 원천 macro 지역 가운데 30셀 이상인 지역을 하나씩 뺀다(`h42.MIN_REGION_CELLS` 와 같다). 30셀 미만 지역(Russia_C, Greenland, Tibet, Scandinavia, Svalbard)은 모든 fold 에서 학습 쪽이다. fold 사이에는 100 km 버퍼를 두지 않는다(LGX N3 의 `h42.select_rows` 와 같다). 심사 단계 계산으로 버퍼 안의 행은 적다: 알래스카에서 100 km 안인 캐나다 셀은 750개 가운데 1개, 캐나다에서 100 km 안인 알래스카 셀은 13,606개 가운데 20개다. 레나 fold 에서는 항상 학습 쪽인 러시아 C(6–7셀)가 레나 셀 3,037개 가운데 1,252개와 100 km 안에 있다. `--count-only` 가 대상별로 fold 지역, 셀 수, fold 학습 행 수, 제외 지역에서 100 km 안인 학습 행 수를 출력하고 개정 이력에 적는다. 조사 단계 계산으로 주 4지역 대상과 Alaska x 는 fold 4개다. 레나 대상의 알래스카 제외 fold 는 학습 행이 약 820행이라 본 적합(14,429행)과 조건이 다르다(배치 2,048 이면 epoch 당 1 step). 이 차이는 N4 에 fold 별 학습 행 수로 적는다 |
| fold 안 적합 | 전처리 통계와 y 척도는 fold 학습 행으로 구한다. 조기 종료 검증은 fold 학습 행의 무작위 10 %(RealMLP 는 pytabkit 의 20 %)다. 종류 D 는 y 를, 종류 R 은 fold 학습 행으로 다시 구한 E_tr 의 잔차 y − E_tr·s 를 학습한다(LGX N3 와 같다). 시도 0 은 4.1 의 코드 경로를 fold 자료에 그대로 적용한다 |
| 주 점수 | λ = 1.0 예측(D 는 ŷ, R 은 E_tr·s + g)의 fold 별 RMSE 를 지역 등가중으로 평균한다(N3 와 같다) |
| 보조 점수 | R 의 λ = 0.25 점수, 셀 가중 점수(fold SSE 합을 채점 셀 수 합으로 나눈 값의 제곱근), 500셀 이상 fold 만의 점수, 시도 0 대비 점수 차. 주 선택에 쓰지 않는다. 셀 가중과 λ 0.25 의 점수는 민감도 선택(아래)에 쓴다. 30셀 fold 두 개가 주 점수의 절반을 차지하므로 보조 기준에서 선택이 바뀌는 (학습기, 종류, 대상) 수를 안정성 지표로 보고한다(Cawley·Talbot 2010, 서지와 초록 요지만 확인) |
| 탐색 | 무작위 탐색이다(Bergstra·Bengio 2012, 서지와 초록 요지만 확인). 1단계는 모든 설정을 seed 0 으로 적합한다. 2단계 후보는 1단계 주 점수 상위(시도 0 제외) 3개(MLP, TabM) 또는 2개(FT-T, RealMLP)와 시도 0 이다. 2단계는 후보를 seed 1·2 로 다시 적합한다. 최종 비교는 seed 1·2 의 평균 점수만 쓴다. 1단계 seed 0 점수는 상위 후보를 고르는 데 썼으므로 최종 비교에 넣지 않는다(상위 후보의 낙관 편향 제거). 2단계는 신경망의 seed 분산 때문에 두며 N3(seed 0 단일 적합)와 다르다 |
| 기본값 우선 규칙 | 2단계 후보 가운데 seed 1·2 평균 주 점수가 가장 작은 설정 c* 가 시도 0 이 아니면 fold 별 차 d_f = S_f(c*) − S_f(0) 로 판단한다(S_f 는 fold f 에서 seed 1·2 평균 RMSE). d̄ 는 d_f 의 fold 평균(지역 등가중), se 는 sd(d_f, 자유도 F − 1)/√F 다. d̄ < 0 이고, −d̄ > se 이거나 d_f < 0 인 fold 수가 ⌈0.75·F⌉ 이상이면 c* 를 고른다. 아니면 시도 0 을 고르고 `sel_default_pref` 표지를 남긴다. fold 가 2개 미만이면 시도 0 을 고르고 `no_cv` 표지를 남긴다. LGX N3(단순 최솟값)와 다른 점이다 |
| 동률과 실패 | 동률이면 매개변수 수(적합한 torch 모듈의 매개변수 수)가 적은 설정을 고른다. 적합 실패나 비유한 예측은 그 fold 점수를 무한대로 둔다. 모두 실패하면 시도 0 을 고르고 `all_failed` 표지를 남긴다 |
| 민감도 선택 | 같은 2단계 후보와 seed 1·2 결과로, 주 점수 대신 (i) 셀 가중 점수(종류 D, R), (ii) λ 0.25 점수(종류 R)를 써서 같은 규칙(기본값 우선 규칙 포함, 셀 가중에서는 d_f 대신 셀 가중 차를 쓰고 fold 승수는 같게 센다)으로 고른다. 추가 fold 적합은 없다. 결과는 `lgfn_select_sens.csv` 에 쓴다. 주 선택과 다른 (학습기, 종류, 대상)만 n = 0 에서 추가로 적합한다(4.4) |
| 적용 | 고른 설정은 그 대상의 모든 분할, n(0 포함), 추출, seed, λ 에 같게 쓴다. D 설정은 D0 에, R 설정은 R1 에 쓴다. 대상 라벨로 다시 고르지 않는다 |
| 시도 0 이 선택된 경우 | 조정판 키를 기본판 키의 값으로 채운다(다시 적합하지 않음). 그 (학습기, 종류, 대상)의 모든 대비는 지역 Δ ≡ 0 이고 지역 부트스트랩 분산도 0 이다. 그런 지역이 층화 평균에 섞이면 점 추정과 CI 폭이 함께 줄어든다(두 지역이 그러면 층화 평균은 나머지 두 지역 Δ 합의 1/4, CI 폭은 절반). 그래서 행과 지역 행에 `sel_default` 표지를 남기고, 층화 평균 행에는 'Δ = 0(선택 결과) 지역 k/4' 열을 두며, 판정 문장은 4.5 의 규칙을 따른다 |
| 기록 순서 | 선택 표 `lgfn_nn_select.csv` 를 그 학습기·대상의 본 적합 전에 쓴다. 열은 대상, 모드, 원천 해시, 학습기, 종류, 시도, 설정 JSON, fold 별 RMSE·SSE·셀 수·학습 행 수, 주·보조 점수, 단계, seed, 선택 여부, 선택 표지, 매개변수 수, epoch 수, 시간이다. 선택 표의 해시를 조각 설정에 넣는다 |

### 4.4 방법과 범위

| 항목 | 내용 |
|---|---|
| 방법 | D0(기준 λ 1.0), R1(기준 λ 0.25, λ ∈ {0.25, 0.5, 1.0} 사후 적용). n = 0 의 R1 은 E_n = E0 인 R 적합(= R0)이다 |
| 판 | 기본판 `<학습기>`(4.1 의 코드 경로, 로컬 재적합)와 조정판 `<학습기>_tuned`(4.3 의 선택 설정). 민감도 판 `<학습기>_tuned_cw`(셀 가중 선택, D0·R1)와 `<학습기>_tuned_l25`(λ 0.25 선택, R1)는 n = 0 에서만 둔다. 민감도 선택이 주 선택과 같은 대상에서는 조정판 키의 값을 복사한다(적합 없음) |
| 동반 적합 | P0, P1(해석식). `catboost_lo` 의 D0·R1(CPU, 로컬 재적합, `h40.cb_fit` 과 같은 초모수, 학습과 채점 Pool 의 thread_count 2). `catboost_tuned_loc` 의 D0·R1(CPU, 로컬 재적합): 설정은 LGX N3 와 같은 절차(h42 의 `TUNE_GRID` 깊이 {3, 6, 8} × 반복 {200, 600, 1,500}, 학습률 `h42.TUNE_LR` 0.05, l2 3, 원천 지역 하나 제외, λ 1.0 주 점수, seed 0, `h42.pick_tuned` 의 동률 규칙)로 이 문서의 fold(4.3)에서 고르고, 적합은 `h42.FitterX` 의 catboost_tuned 와 같은 인자(random_seed = 학습기 seed)다. 스레드만 2 로 다르다(LGX 는 4). LGF-N3 의 주 비교 대상이다. 사전 점검에서 잰 CPU 시간 환산(선택과 본 적합)이 8 h(2스레드 프로세스 1개)를 넘으면 돌리지 않고 N3 의 주 비교 대상을 `catboost_lo` 로 바꾼다(4.5) |
| 대상 | 1순위: 주 4지역 x. 2순위: Alaska x(3지역 보조 열용) |
| 분할 | 1–5(주 4지역은 5개 모두 유효) |
| n 격자 | {0, 10, 40, 160, 전량} 가운데 \|A\| 미만과 전량. 러시아 W·E 는 {0, 10, 전량} |
| 추출 × seed | 2 × 2(LG 학습기 축과 같다) |
| 통과 0(n = 0) | n = 0 의 학습 행(원천)과 학습기 seed 는 분할과 무관하다. 그래서 신경망은 (학습기, 판, 종류, seed, 대상)마다 한 번 적합해 대상 셀 전체를 예측하고, 분할마다 B 채점 셀로 잘라 쓴다(공유 적합). 기본판의 공유 적합도 `h40.Fitter.fit`(4.1 의 코드 경로)을 그대로 부른다. 분할 사이 GPU 비결정성으로 값이 달라지는 문제도 없어진다. P0 는 분할마다 저장한다. 조각의 `unit.json` 에 `shared_n0` 표지를 남긴다. 확인적 가설 N1 의 구성 단위이므로 먼저 돈다(8.4 의 J3, J5) |
| 통과 1(n > 0) | 분할마다 적합한다. 기본판은 `h40.run_ctx` 로, 조정판은 같은 (n, 추출, seed) 칸의 같은 학습 행으로 적합한다 |

적합 수(1순위, 학습기 하나, 판 하나): 통과 0 은 16건(대상 4 × 종류 2 × seed 2), 통과 1 은 레나 140, 캐나다 140, 러시아 W 60, 러시아 E 60, 합계 400건이다. 민감도 판은 (학습기, 대상)마다 최대 6건(대체 설정 3 × seed 2), 1순위 합계 최대 96건이다. 선택 단계의 fold 적합(1순위, 대상 4 × fold 4 = 16): MLP·TabM 은 1단계 33 × 2 × 16 = 1,056 과 2단계 4 × 2 × 2 × 16 = 256, FT-T 는 576 과 192, RealMLP 는 544 와 192 다. E1(8.4)을 적용하면 FT-T 의 1단계는 1,088, RealMLP 는 1,056 이다. 2순위(Alaska x)는 판마다 통과 0 4건, 통과 1 140건과 fold 4개다. `catboost_lo` 와 `catboost_tuned_loc` 는 분할마다 적합해 각각 480건(2순위 160건)이고, `catboost_tuned_loc` 의 선택은 9 설정 × 종류 2 × fold 4 × 대상 5 = 360건이다.

### 4.5 가설과 판정(결과 열람 전 고정)

l ∈ {`mlp`, `tabm`, `ftt`, `realmlp`}, l* = `l_tuned`, CB = `catboost_lo`(로컬), CBT = `catboost_tuned_loc`(로컬). 네 학습기는 판별 신경망 4종(MLP, 다중 헤드 MLP, 축소 FT-Transformer, RealMLP)이다. 생성 학습기(cfm, ddpm, nflow)는 포함하지 않는다. 모든 대비는 기준 λ 와 4분 판정을 쓰고, 따로 적지 않으면 주 4지역 층화 평균이다.

| id | 가설 | 판정 |
|---|---|---|
| LGF-N1 (조정한 신경망의 라벨 0 직접 예측, 확인적) | 원천 지역 하나 제외 교차검증으로 초모수를 고른 판별 신경망 4종의 직접 ML 도 라벨 0 전이에서 원천 계수 물리식을 넘지 못한다 | 판정 대비는 학습기마다 n = 0 의 D0[l*] − P0(λ 1.0)다. 네 대비 모두 우세가 아니면 지지, 하나라도 우세이면 기각이다. 지지는 학습기마다 2.2 의 두 갈래로 적는다. 네 학습기가 모두 '지지(물리식보다 오차가 크거나 구별되지 않음)'이면 문장은 '원천 지역 하나 제외 교차검증으로 초모수를 골라도 시험한 판별 신경망 4종(MLP, 다중 헤드 MLP, 축소 FT-Transformer, RealMLP)의 직접 ML 은 라벨 0 전이에서 원천 계수 물리식을 넘지 못한다'다. '지지(우세 근거 없음)'인 학습기는 문장에서 빼고 '조정한 <학습기> 에서 우세가 관찰되지 않았다(CI [a, b] cm)'로 따로 적는다. 기각이면 L1 의 라벨 0 부분 결론을 '기본 초모수 한정'으로 적고, 해당 학습기의 조정판 D0 곡선을 플랫폼 표지와 로컬 기본판·`catboost_lo` 곡선과 함께 마스터 곡선에 더한다(2.2). 판정 행에 학습기별 'Δ = 0(선택 결과) 지역 k/4'(종류 D)를 적는다. 보조 행(판정에 쓰지 않음): (a) 로컬 기본판의 D0[l] − P0(n = 0), (b) n ∈ {10, 40} 의 D0[l*] − P0, (c) L1 형식의 지역 수(주 4지역 가운데 n ∈ {0, 10, 40} 의 어느 n 에서든 D0[l*] − P0 의 지역 블록 CI 상한 < 0 인 지역의 수. N 의 격자에 n = 3 은 없다), (d) 3지역 보조 열(2순위를 돌렸을 때), (e) 민감도 판 D0[l_tuned_cw] − P0(n = 0) |
| LGF-N2 (조정 효과) | 조정판과 기본판의 차이는 동등성 한계 안이다 | 학습기마다 R1[l*] − R1[l](λ 0.25 와 1.0)과 D0[l*] − D0[l](λ 1.0)을 n ∈ {0, 10, 전량} 에서 본다(대비 9개). 판정 행마다 종류별 'Δ = 0(선택 결과) 지역 k/4' 열을 두고, k ≥ 1 이면 판정 문구 앞에 이를 적는다. 갈래는 다섯이다. (i) 9개 모두 동등이면 '강건 후보(한계 0.5 cm)'. (ii) 우세만 있으면 '조정판의 오차가 작다(대비, n, 크기)'이고 조정판은 LGF 의 N3 표로 보고한다(L5·L26 에 병기하지 않는다, 2.2). (iii) 열세만 있으면 '원천 교차검증 조정이 전이 오차를 키웠다(대비, n, 크기)'. (iv) 우세와 열세가 함께 있으면 '혼재'. (v) 그 밖은 '차이를 확인하지 못함'이고 2.2 의 정밀도 표기를 붙인다. 2.2 의 λ 조합 규칙과 보조 한계 병기를 쓴다. n ∈ {40, 160} 은 보조다. 강건 문장 규칙: 학습기 하나에 '초모수 선택에 강건하다'고 쓰려면 (i) 이고, 시도 0 이 아닌 설정이 선택된 지역만으로 계산한 보조 층화 평균(지역 4 − k 개, 대비의 종류마다 따로)에서도 같은 대비가 모두 동등이어야 한다. k = 4 이면 '원천 교차검증 조정 절차는 모든 대상에서 기본 설정을 골랐다(조정판 = 기본판)'로만 쓴다. (i) 이지만 보조 층화 평균이 동등이 아니거나 계산할 수 없으면 '원천 교차검증 조정 절차를 적용해도 차이는 한계 안이다(선택 결과 Δ = 0 지역 k/4 포함)'로 쓴다. 문장 '신경망의 결론은 초모수 선택에 강건하다'는 네 학습기 모두 강건 문장 규칙을 채울 때만 쓴다. 보조 행: 민감도 판의 n = 0 대비 R1[l_tuned_cw] − R1[l], R1[l_tuned_l25] − R1[l], D0[l_tuned_cw] − D0[l] |
| LGF-N2s (판정 안정성, 보조) | 핵심 대비의 4분 판정은 기본판과 조정판에서 같다 | 학습기마다 핵심 대비 D0 − P0(n = 0), R1 − P1(n = 10, 전량), R1 − P0(전량), R1 − CBT(n = 0, 10, 전량. CBT 가 없으면 CB)를 기본판과 조정판으로 각각 계산한다. 4분 판정이 같거나 동등과 미결정 사이의 변화이면 '강건', 우세·열세와 동등·미결정 사이의 변화는 '약화', 우세와 열세가 바뀌면 '의존'이다(LG L28 과 같은 규칙). '의존'인 대비는 한계 절에 조건을 적는다. 심사 지적('신경망이 조정되지 않았다')에 대한 답은 이 행으로 쓴다. 모든 학습기·핵심 대비가 강건이면 '초모수를 원천 교차검증으로 골라도 핵심 판정은 바뀌지 않았다'. 'Δ = 0(선택 결과) 지역 k/4' 를 함께 적는다 |
| LGF-N3 (CatBoost 대비) | 조정한 신경망과 조정한 CatBoost 의 R1 차이는 동등성 한계 안이다 | L26 과 같은 형식이다. R1[l*] − R1[CBT] 를 n ∈ {0, 10, 전량} 에서 본다. 모두 동등(λ 0.25 와 1.0)이면 '동등(한계 0.5 cm, 양쪽 조정)', 우세와 열세가 없고 미결정이 있으면 '차이를 확인하지 못함'(2.2 의 정밀도 표기), 우세·열세는 표로 보고한다. 2.2 의 λ 조합 규칙과 보조 한계 병기를 쓴다. 보조: R1[l*] − R1[CB], 로컬 기본판의 R1[l] − R1[CB], D0 의 같은 대비. CBT 를 돌리지 못하면(4.4 의 CPU 조건) 주 비교 대상을 CB 로 바꾸고, 판정 문구를 '조정 신경망 대 고정 초모수 CatBoost(반복 200, 깊이 3)'로 한정한다. 이 경우 '양쪽 조정' 문장을 쓰지 않는다(9.2) |
| LGF-N4 (서술) | 없음 | 선택 표, 원천 교차검증에서 선택 설정과 시도 0 의 점수 차(seed 1·2 평균), 기본값 우선 규칙 표지 수, 보조 기준에서의 선택 안정성, `sel_default` 수, fold 별 학습 행 수, 원천 교차검증 점수 차와 대상 Δ(l* − l, n = 0)의 관계(점 (학습기, 종류, 대상) 32개의 순위 상관, 검정 없음), 설정별 적합 시간과 epoch 수, `catboost_tuned_loc` 의 선택 표 |

**판정 세부 규칙(N)**

| 항목 | 규칙 |
|---|---|
| 풀 | 2.2 와 같다 |
| L1 과의 관계 | N1 이 고칠 수 있는 범위는 L1 의 라벨 0 부분이다. '지지(물리식보다 오차가 크거나 구별되지 않음)'인 학습기만 라벨 0 부분의 '학습기 종류와 무관' 근거 목록에 '조정한 <학습기>'로 더한다. 보조 행 (c)에서 우세 지역이 2개 이상인 학습기가 있으면 N1 의 판정과 별도로 L1 결론에 '조정한 <학습기> 는 n ≤ 40 에서 예외(지역, n)'를 적는다. 보조 행 (b)에 우세인 n 이 있으면 그 n 을 L1 결론의 한계로 적는다 |
| 판정할 수 없는 대비 | N1 은 확인적 규칙(6A.5a)을 따른다. 네 학습기 대비 가운데 4분 판정이 나온 대비가 k < 4 이면 지지 문구를 쓰지 않는다. 판정이 나온 대비에 우세가 있으면 '기각(일부 대비 판정 불가, 대비 k/4)', 아니면 '판정 불가(대비 k/4; 없는 대비: …)'. N2, N3 은 k < m 이면 판정 불가이되 판정이 나온 대비의 우세·열세는 보고하고 '부분(대비 k/m)'을 붙인다. N2s 는 대비마다 분류하고 대비가 없으면 그 대비만 판정 불가다 |
| 분할 완결성 | N1 은 분할 미완결이면 '판정 불가(분할 k/K)'. 통과 0 은 공유 적합이므로 분할 완결성은 분할별 P0 조각과 공유 적합 조각이 모두 있는지로 정한다. N2, N3, N2s 는 '부분(분할 k/K): ' |
| 조정판 = 기본판 | 학습기·종류 하나에서 네 대상 모두 시도 0 이 선택되면 판정 행에 '조정판 = 기본판(선택 결과)'을 적는다. 이때 N1 은 로컬 기본판의 대비와 같다. 일부 대상만 그렇면 'Δ = 0(선택 결과) 지역 k/4' 열과 지역 행의 `sel_default` 표지로 적는다(N1, N2, N2s, N3 공통) |
| Holm 묶음(보조 열) | 확인적 묶음: N1 의 4개. 보조 묶음: N2 의 기준 λ 대비 24개(학습기 4 × n 3 × 방법 2)와 N3 의 주 비교 12개로 36개. N2, N3 의 동등성 p 는 따로 한 묶음으로 보정한다. 판정에 쓰지 않는다. 보조 묶음에서 보정 뒤 p ≥ 0.05 인 우세·열세에는 '보정 전 유의'를 붙인다 |
| 교차 환경(보조) | LG 본 실행 결과를 회수한 뒤 로컬 기본판과 LG 조각(Rescale)의 같은 키를 대조해 `lgfn_cross.csv` 에 '교차 환경(보조)'로 적는다. 앞서 P0, P1 이 1e-9 cm 안에서 같은지 확인한다. 플랫폼 차이(하드웨어, torch·numpy 판)가 신경망 적합에 주는 영향의 크기를 서술하는 표이며 판정에 쓰지 않는다 |
| 맹검 표지 | 5절의 표를 따른다 |

2. `--count-only`(스레드 1): 작업 단위, 적합 수, fold 구성(fold 학습 행 수, 제외 지역 100 km 안의 학습 행 수 포함), 설정 목록(`lgfn_configs.json`, E1 목록 포함)을 확정하고 개정 이력에 적는다.
3. 스모크(10분 이내, 빈 후보 GPU 한 장): h47 은 Russia_W x·Canada x, 분할 1, n {0, 10, 40, 전량}, 추출 1, seed 1, 주 설정과 full. h48 은 Canada x, 분할 1, n {0, 10}, 추출 1, seed 1, 학습기 4종(epoch 3), 선택은 시도 0·1 과 fold 전부. 스모크 집계는 곡선과 판정 표를 쓰지 않고 Δ 와 판정을 화면에 내지 않는다(LG 6C 개정 12 와 같다). 경로 점검(ctx_sha 가 h43 의 구성과 같은지, n = 0 의 R1 = R0, 가중치 캐시 하위 클래스와 원래 클래스의 예측 차, 묶음 예측 차, 조정판 학습 행이 h40 의 학습 행과 같은지, 통과 0 공유 적합의 분할별 자르기가 분할별 적합의 채점 셀과 같은지)과 시간만 낸다.
4. 사전 점검(시간 측정, 판정 없음). 산출 제한은 스모크와 같다. RMSE, Δ, 판정, 선택 점수를 출력하거나 파일에 쓰지 않는다. 적합 시간, epoch 수, GPU 메모리, 최대 RSS, 적합 수만 기록한다. 사전 점검 조각은 별도 tag(`lgf_pre`, `lgfs_pre`, `lgfn_pre`)로 쓰고 본 실행에 재사용하지 않으며 집계에서 뺀다.
   - h47: 레나 x 분할 1(주 설정 n {0, 40, 전량}, full n {0, 40, 전량}), Alaska x 분할 5(주 설정 n {0, 40, 전량}. 채점 행 7,284 로 가장 많다), Russia_W x 분할 1 의 full n = 0(컨텍스트 약 17,400행으로 가장 많다). 추출 0, seed 0.
   - h48: (a) 고정 목록의 모든 설정(MLP·TabM 33, FT-T 34, RealMLP 33. E1 목록 포함, 종류 D)을 레나 x 원천 전체에서 2 epoch 씩 적합해 설정별 epoch 당 시간을 잰다(RealMLP 는 `n_epochs=2`). (b) 학습기마다 시도 0 과 무작위 시도 2개(시도 번호 1, 2. FT-T 는 2, 3)의 전체 적합(seed 0, 레나 x 의 캐나다 제외 fold)으로 실제 epoch 수를 잰다. (c) 기본판 통과 0 공유 적합 1건과 통과 1 적합 2건(n = 10, 전량)의 시간. (d) `catboost_tuned_loc` 의 선택(레나 x, 9 설정 × 종류 2 × fold 4, 2스레드) 시간과 9 설정의 원천 전체 적합 1건씩의 시간. (e) RealMLP 표본 설정의 키가 모두 `RealMLP_TD_Regressor` 생성자 인자인지 `inspect.signature` 로 확인.
5. 사전 점검 개정(본 실행 전, 결과 열람 전): 8.3 의 식으로 P 를, 8.1 로 B 를 계산하고 E1 여부와 축소 단계(8.4)를 정해 개정 이력에 적는다. 열람 상태 칸, 창 시작 예정 시각, `catboost_tuned_loc` 실행 여부(4.4 의 8 h 조건), TabICL 2.0.3 이후 판의 변경 기록 확인 결과(3.1)를 함께 적는다.
6. 본 실행: 단일 큐(8.4 의 J1–J12)와 CPU 작업(C1). GPU 한 장이면 J 순서대로 차례로 돈다. 두 장 이상이면 h47 은 한 장에서 F 작업(J1, J6, J8, J9, J11, J12)을, h48 은 나머지에서 N 작업(J2, J3, J4, J5, J7, J10)을 각자의 순서로 돈다. 한쪽이 끝나면 그 GPU 를 다른 쪽에 더한다(드레인 뒤 `--gpus` 를 늘려 `--resume`). GPU 가 늘거나 줄 때는 6.1 을 따른다. C1 은 본 실행 시작과 함께 GPU 없이 돈다.
7. 집계(`--summarize-only`, 스레드 2, GPU 없음). 본 실행 중에는 LGF 를 집계하지 않는다(`--no-summarize`). 판정용 집계는 기본 범위(J1–J11)가 끝나거나 창이 마감된 뒤 한 번 한다. F 는 LGT 조각이 있으면 3.4 의 조건으로 짝을 병합한다. 그때 LGT 가 끝나지 않았으면 F3·F4 의 T 열은 분할 완결성 규칙으로 표시하고, LGT 가 끝난 뒤 다시 집계하며 재집계 사실과 시각을 개정 이력에 적는다. J12 는 끝난 뒤 따로 집계한다.

## 8. 시간 추정, 창, 축소 규칙

### 8.1 창과 예산

- 창: 본 실행의 첫 작업 단위가 시작된 시각 t0 부터 48 h 다. 하네스는 t0 를 `lgf_window.json` 에 처음 한 번만 쓰고(이미 있으면 바꾸지 않는다), 마감은 t0 + 48 h 다. 사전 점검 개정(6.3 단계 5)에 t0 의 예정 시각을 적는다. 48 h 는 GPU 한 장으로도 확인적 구성 단위와 선택 단계(J1–J5)와 F 1순위(J6)를 낙관값(8.4)으로 마칠 수 있는 길이로 정했다(약 25 GPU-h).
- B: 창 안에서 LGF 가 쓸 것으로 예상되는 GPU-시간이다. 사전 점검 개정 시점에 다음 합으로 한 번 계산해 고정한다. (i) 그 시점에 점유 판정을 통과한 사전 허용 후보(2, 3, 4, 5) 각각 48 h. (ii) GPU 6·7·9 각각: LGT 가 끝났으면 48 h, 끝나지 않았으면 max(0, 48 − (LGT 예상 종료 − t0)) h. LGT 예상 종료는 그 시점 + (남은 단위 수 × 완료 단위의 평균 벽시계 ÷ 워커 수)이고, `lgt_run.log` 의 완료 수와 누적 시간(진행 정보이며 결과가 아니다)으로 구한다. 사용자가 6·7·9 의 사용을 막았으면 넣지 않는다. (iii) LGU 가 로컬로 개정되어 LGF 와 GPU 를 나눌 예정이면 2 GPU-h 를 뺀다.
- B 를 정한 뒤 GPU 가 더 생기면 8.4 의 복원 규칙만 적용하고 B 를 다시 쓰지 않는다. GPU 가 줄면(다른 사용자의 점유) 창 마감까지 끝나지 않은 단위는 판정 규칙(분할 완결성, 풀 지역 수)으로 처리한다.
- 참고 시나리오(결정에 쓰지 않는다): GPU 5 한 장이고 LGU 를 나누면 B = 46 GPU-h 다. t0 에 LGT 가 이미 끝났으면 GPU 5·6·7·9 로 B = 192 GPU-h, t0 + 12 h 에 끝나면 48 + 3 × 36 = 156 GPU-h 다.
- Rescale 비용은 0 이다. CPU 는 LGF 프로세스 안의 CatBoost·전처리와 CPU 작업 프로세스 하나(2스레드)다.

### 8.2 F 추정

TabICL 적합 1건의 시간은 재지 않았다. 기준은 LGT 의 TabPFN 추정식 t_T = 0.5 + (6.7 + 0.6 × 채점 행 수/1,000) × (컨텍스트 행 수/9,900) s 다. LGT 스모크 실측(`lgt_smoke_fit_timing.csv`, RTX 3090)에서 TabPFN 은 컨텍스트 9,000–9,400행, 채점 200–400행에서 적합 1건 5.6–6.1 s 였고 추정식 값은 6.7–7.1 s 였다(가중치 적재를 포함한 첫 적합은 12.6–19.4 s). LGT 본 실행의 첫 단위(러시아 W x 분할 1, 적합 140건)는 424 s 로 추정식 합(약 462 s)의 0.92배였다. 추정식은 TabPFN 에 대해 약 10–15 % 보수적이다. TabICL 은 이 식에 배율 r ∈ [0.5, 1.5](기준 1.0)을 곱한다고 가정한다. 근거는 합성 자료 점검(500행 적합 1.22 s)뿐이다. full 은 컨텍스트가 1.4–1.8배라 선형 가정의 값에 2배까지의 여유를 두었다(어텐션 계산량은 행 수의 제곱에 가깝게 늘 수 있다). - 2순위(Alaska x, 원천 3,860행)는 선택 약 1.3 · 3.2, 본 적합 약 2.3 · 4.5 로 합계 약 3.6 · 7.7 GPU-h 다(거친 추정).
- CPU: `catboost_lo` 는 640건, 약 0.1 h 다. `catboost_tuned_loc` 는 선택 360건(설정별 시간 미측정. LGX 사전 점검에서 4스레드 CatBoost 600회·깊이 6 이 약 1.5 s 였다)이 2스레드로 약 0.5 h, 본 적합 640건이 선택 설정에 따라 약 0.1–5 h 로 추정된다. 사전 점검에서 재어 8 h 를 넘으면 돌리지 않는다(4.4).
- 사전 점검 뒤의 P 계산: 조정판 설정 c 의 fold 적합 시간 = (설정별 epoch 당 시간, 6.3 단계 4(a)) × (fold 학습 행 비) × E_c. E_c 는 MLP·TabM·FT-T 에서 min(최대 epoch, 1.25 × 사전 점검 (b)의 학습기별 평균 epoch 수), RealMLP 에서 256 이다. 본 적합은 fold 비 대신 1 을 쓰고, 기본판은 (c)의 실측을 쓴다. F 는 사전 점검의 TabICL 실측으로 r 을 정해 8.2 의 식에 넣는다.

### 8.4 단일 큐, 합계, 축소·확장 규칙(결과 열람 전 고정)

**단일 큐**: GPU 가 한 장이면 아래 순서로만 돈다. 두 장 이상이면 6.3 단계 6 의 방식으로 F 와 N 을 나누되 각 스크립트 안의 순서는 이 표를 따른다. 확인적 가설 F1 의 구성 단위(J1)와 N1 의 구성 단위(선택 단계와 통과 0, J2–J5)가 먼저 채워지도록 정한 순서다.

| 순위 | 작업 | 스크립트 인자 | 내용 | GPU-h(낙관·비관) |
|---|---|---|---|---|
| J1 | F 1순위 n = 0 | h47 `--jobs f_n0` | 주 4지역, 분할 1–5, 주 설정 D0·R0 과 full D0@full·R1@full 의 n = 0 | 0.4 · 1.0 |
| J2 | N 선택(빠른 학습기) | h48 `--jobs n_sel_fast` | MLP, TabM 의 1·2단계(주 4지역) | 3.6 · 8.2 |
| J3 | N 통과 0(빠른 학습기) | h48 `--jobs n_p0_fast` | MLP, TabM 의 기본판·조정판 공유 적합과 민감도 판 | 0.2 · 0.3 |
| J4 | N 선택(느린 학습기) | h48 `--jobs n_sel_slow` | FT-T, RealMLP 의 1·2단계 | 14.9 · 37.8(E1 이면 25.0 · 63.4) |
| J5 | N 통과 0(느린 학습기) | h48 `--jobs n_p0_slow` | FT-T, RealMLP | 1.3 · 3.0 |
| J6 | F 1순위 n > 0 | h47 `--jobs f_t1` | | 4.7 · 7.0 |
| J7 | N 통과 1(1순위) | h48 `--jobs n_p1` | 빠른 학습기 먼저, 분할 번호 순 | 19.5 · 37.5 |
| J8 | F full n > 0 | h47 `--jobs f_full` | | 1.4 · 4.2 |
| J9 | F 2순위 Alaska x | h47 `--jobs f_t2ak` | | 1.4 · 2.1 |
| J10 | N 2순위 Alaska x | h48 `--jobs n_t2` | 선택, 통과 0, 통과 1 | 3.6 · 7.7 |
| J11 | F 2순위 나머지 | h47 `--jobs f_t2` | 7대상 | 5.0 · 7.6 |
| J12 | F 3순위(조건부) | h47 `--jobs f_t3` | 15대상 | 17.3 · 25.9 |
| C1 | CPU 작업 | h48 `--jobs n_cb --cpu-only` | `catboost_lo`, `catboost_tuned_loc` 의 선택과 적합(GPU 없음, 2스레드) | CPU 약 0.6–5.6 h |

**합계(기준 추정)**: 기본 범위(J1–J11)는 낙관 약 56 GPU-h(F 12.9, N 1순위 39.5, N 2순위 3.6), 비관 약 116 GPU-h(F 21.9, N 1순위 86.8, N 2순위 7.7)다. E1 을 더하면 낙관 약 66, 비관 약 142 GPU-h 다. J12 는 17.3–25.9 GPU-h 를 더한다.

**결정 절차(사전 점검 개정에서 한 번)**: 측정 기반 P(J1–J11)와 B(8.1)로 정한다.
1. P + ΔE1 ≤ B 이면 E1 을 적용한다(FT-T·RealMLP 무작위 32. 목록은 시도별 seed 라 앞 16개는 같다).
2. 아니고 P ≤ B 이면 바꾸지 않는다.
3. P > B 이면 아래 단계를 차례로 적용해 P ≤ B 가 될 때까지 줄인다.

| 단계 | 줄이는 것 | 기준 추정에서 줄어드는 양(낙관·비관) |
|---|---|---|
| S1 | N 2순위(J10) 제외 | 3.6 · 7.7 |
| S2 | F full 변형의 n > 0(J8) 제외. n = 0 의 D0@full·R1@full(J1)은 F1 의 구성 대비라 남긴다 | 1.4 · 4.2 |
| S3 | F 2순위 나머지(J11)의 추출 5 → 2(n ∈ {3, 10, 40, 160, 320, 1,000}, 추출 번호 0·1) | 약 2.8 · 4.3 |
| S4 | F 2순위 나머지(J11) 제외(2순위는 Alaska x 만 남는다) | S3 뒤 남은 J11 |
| S5 | N 통과 1 의 추출 2 → 1(n ∈ {10, 40, 160}, 추출 번호 0) | 7.8 · 15.0 |
| S6 | N 통과 1 의 분할 1–5 → 1–3. 통과 0 은 분할 1–5 를 유지한다 | S5 뒤 남은 J7 의 40 % |
| S7 | MLP·TabM 의 무작위 32 → 16(고정 목록의 앞 16개) | 1.4 · 3.2 |

- 초판의 S4(FT-T·RealMLP 16 → 8)는 없앴다. 무작위 횟수의 하한은 네 학습기 모두 16 이다(문헌 기준: Gorishniy 2021 TPE 100회, TabM README 30–50회, Holzmüller 2024 RealMLP-HPO 무작위 50회. 설정 수를 줄이는 단계는 '조정하지 않았다'는 지적에 대한 근거를 줄이므로 가장 나중에 둔다).
- 줄이지 않는 것: J1–J5 전체(F1 과 N1 의 구성 단위, N 의 선택 단계), J6(F2–F5 의 주 4지역 대비).
- S7 뒤에도 P > B 이면 더 줄이지 않고 멈춰 사용자에게 보고한다. 사용자의 범위 결정은 열람 상태 칸과 함께 개정 이력에 적는다.
- 복원 규칙: B 를 정한 뒤 GPU 가 더 생겨(6.1) 창의 남은 시간 × LGF 가 쓰는 GPU 수로 본 여유가 되돌릴 단계의 추정량보다 크면, 줄인 단계를 역순(S6, S5, S4, S3, S2, S1)으로 되돌려 큐 끝에 넣는다. S7 과 E1 은 해당 학습기의 1단계 선택이 시작된 뒤에는 바꾸지 않는다. 복원은 결과와 무관하게 GPU 시간만으로 정하고, 적용 시각과 GPU 수를 `lgf_window.json` 과 개정 이력에 적는다.
- J12(F 3순위)는 J1–J11 이 모두 끝났을 때 창의 남은 시간 × 그 시점에 LGF 가 쓰는 GPU 수가 J12 의 측정 기반 추정보다 크면 돈다. 아니면 돌지 않고 LGT 의 TabPFN 결과만 해당 대상에 남는다.
- 창 마감 뒤에는 새 단위를 시작하지 않는다. 끝나지 않은 작업의 판정은 6A.5a 의 규칙(분할 완결성, 풀 지역 수)으로 처리한다.
- 적용한 단계와 이유(측정값, P, B, E1)를 `lgf_projection.csv`, `lgf_window.json`, 개정 이력에 적는다. S5 를 적용하면 N 의 n ∈ {10, 40, 160} 곡선은 추출 1개로 계산된다는 점을 표에 적는다.

### 8.5 확인하지 못한 것

- TabICL 의 적합 1건 시간(컨텍스트 3,860–17,437행, 채점 최대 7,284행)과 GPU 메모리. 컨텍스트 행 수에 대한 시간 의존(선형 가정).
- RTX 3090 과 T4 의 속도비(2–3배 가정), 조정판 설정의 적합 시간(낙관·비관 두 가정), 조정판의 실제 epoch 수.
- `catboost_tuned_loc` 의 CPU 시간. CatBoost 의 스레드 수(2와 4)에 따른 재현성.
- LGT 의 남은 시간(첫 단위 424 s, 작업 단위 172)과 다른 사용자가 GPU 0–4 를 쓰는 기간.
- 동등성 한계 0.5 cm 의 문헌 근거(LG 6A.2 와 같이 확인하지 못했다).

### 9.2 쓰지 않을 문장
